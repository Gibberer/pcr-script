# 斗技场：本期满星与领奖

`battle_stadium` 以本期回合三星和累计报酬全部领取为目标。GUI 可在按需专项选择，CLI 使用：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py battle_stadium --config daily_config.yml
```

每次运行核对实际星级及领奖状态，满星且全部领取后不再挑战。后续回合未解锁时返回 `partial`，解锁后重新运行接续。活动情报包含挑战期及后续领奖期，领奖期只领取已有报酬。默认不加入完整日常列表；希望自动接续时可添加 `[battle_stadium]`。

GUI 与 CLI 共用根目录 `runtime_defaults.yml` 的 `BattleStadium` 段：

| 选项 | 默认 | 含义 |
|---|---|---|
| `max_battles` | 36 | 本次合计挑战上限 |
| `max_attempts_per_round` | 2 | 本次每回合最多实战方案数 |
| `timeout` / `battle_timeout` | 7200 / 180 秒 | 任务及单场等待上限 |
| `claim_rewards` | `true` | 领取累计报酬，关闭时不报告全奖励完成 |
| `discover_sources` | `true` | 自动搜索本期攻略 |
| `source_urls` | `[]` | 本任务优先视频链接 |
| `allow_local_trials` | `true` | 来源出战成员明确但培养不完整时，核验当前账号后有限试打 |
| `auto_equip` / `auto_equip_priorities` | `false` / `{}` | 核验队伍和槽位后按游戏自动设定重新分配现有特别装备，可指定已支持的优先属性 |
| `account_key` | `default` | 账号恢复隔离键，切换账号需使用不同键 |
| `sources` | `{}` | 共用视频解析及公共头像选项 |
| `sources.refresh_media` | `false` | 重新取得视频并解析，完成排查后可关闭；下载预算及识别要求不变 |

程序自动获取来源、媒体及公开头像，不需要 Agent 提前准备真实队伍文件。来源必须属于本期、确认国服与具体回合，全部出战成员在至少两帧一致识别。支持一至五人队伍；少于五人时还须确认其余编队槽为空，且实际战斗中的成员与最终编队一致。选人过程的临时队伍不作为攻略。作者补充未完整读取、存在未支持的装备／全局条件或手动操作时不能采用。`allow_local_trials` 不表示复现原攻略；身份、等级、Rank、星级、技能、独立专武及特别装备仍须核验，未知时停止。

斗技场来源默认每分P最多解析600帧，均匀覆盖整段合集，并在具体回合详情之后使用预算内帧数加密编队与战斗过渡。可通过 `sources.max_frames_per_page` 降低预算；不足以核验短画面时返回来源不足，不猜测队伍。

多个队伍可用时，优先选择来源中有连续胜利结算证据的方案；仅有明确败北证据的方案不试打。胜利证据只能调整顺序，当前账号的战前核验与战后星级复核仍必须通过。

后台搜索经有限重试仍未确认输入时，程序先核对编队页面、清空搜索并关闭安卓输入条，再扫描完整角色列表。扫描在卡片间空隙滑动列表正文并保留行重叠，避开右侧细滚动条。列表扫描仍核验完整衣装、培养及最终编队，不能把输入失败解释为缺少角色。

斗技场强制自动且技能值从零开始，来源通常不声明技能等级。搜索结果的公开头像已确认完整衣装时，只读人物详情的等级、Rank、星级与专武，不再进入技能页；头像无法确认身份或来源声明了技能等级时才读取技能。

编队徽标不能明确专武状态时，程序使用人物页只读核对尚未实装状态及来源要求的专武数值，再回到目标回合重新选人并完整检查；仍未知时停止。任务不自动培养角色、安装或强化专武、购买资源、回复次数或重置进度。斗技场的强制自动战斗与常规 SET/AUTO 不同，见[游戏规则](../game-knowledge/battle-stadium.md)。

`auto_equip: true` 复用公共特别装备分配流程，提交后重读槽位，并在开战前重验出战成员。游戏当前自动设定可能取用其他角色的装备；无变化时取消预览。可通过 `auto_equip_priorities: {armor: hp, accessory: hp}` 指定生命值优先，其他类别沿用游戏设置；支持值与[追忆战指南](recollection.md)相同。此选项只重新分配已有装备，不强化或购买，也不能代替来源指定装备及全局条件的核验。

战后重读回合星级，不以胜利动画或程序退出表示全部完成。开战与领奖前保存待核对记录；结算未知时停止，重跑先核对原结果，不重放。未满星队伍按本期回合、培养及配装记录，条件不变时不重复试验。

只读人物核验或搜索中断后，重跑先关闭已确认的人物详情或安卓输入条，再退出未开战编队并重新识别回合。

累计报酬还须满足当前实际星数；未达到门槛的行即使按钮保留蓝色，也不会领取。星数与回合总数须明确读取，模糊数字不会按预期进度补写。

当前来源没有可用新方案时，自动排除已检查来源并继续获取本期精确回合作业；每回合共用 `sources.max_videos` 预算（默认4个），元数据、作者补充读取或解析失败也占用预算。实战仍受 `max_attempts_per_round` 和 `max_battles` 约束，不为换来源扩大上限。

重跑优先寻找本期该回合尚未试过的出战成员组合。以前未满星的组合保留作后备，只有重新核对培养或配装的实际变化后才可能再次试打；这项排序不替代战前核验。

显式更改自动分配优先属性后，可先复核已有的已验证来源，不必先耗尽搜索预算。优先属性变化只触发复核；实际装备与已失败配装相同时仍不重打。

优先处理已解锁但尚未获得星级的回合，再回到已胜利的回合补星。某回合仍缺可用方案时，记录未满星原因并继续其他已解锁、核验通过的回合。全部可执行回合处理后仍有缺口则返回 `partial`，重跑会重新核对这些回合。

报告和证据在当前运行目录，账号恢复记录位于忽略的 `cache/game/battle_stadium/`。未解锁、来源不足、核验失败、预算用尽或待核对结果均返回 `partial`。真实连续满星与冷缓存验收范围见[工程待办](../pending-validation.md)。
