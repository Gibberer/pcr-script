# 黎明界迷宫

提供两个独立任务，默认都不加入任务列表：

| 任务 | GUI 入口 | 用途 |
|---|---|---|
| `dawn_labyrinth_first_clear` | 按需专项 → 黎明界迷宫 · 难度1首通 | 美食殿堂难度 1 的一次探索；中断时保留进度。 |
| `dawn_labyrinth` | 每日日常 → 黎明界迷宫 · 扫荡通行证 | 对已解锁的难度执行跳过，消耗现有通行证。 |

两项均从冒险进入黎明界迷宫，GUI 可通过“＋ 添加任务”添加，也可使用单项命令：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dawn_labyrinth_first_clear --config daily_config.yml
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dawn_labyrinth --config daily_config.yml
```

首次使用可将首通任务、扫荡任务依次添加到 GUI 或配置的任务列表；首通完成后回到难度 1 并核对跳过已解锁，随后扫荡消耗剩余通行证。已经首通时，首通任务只核对状态，不消耗通行证；零通行证时两项也可重复运行。

两项正常结算后都会检查迷宫首页的“任务”角标，有奖励时进入“全部”并点击“全部收取”。程序保存领取回执，核对后续奖励、按钮禁用和首页角标消失后才完成；已通关复查、零票扫荡及达到消费上限后也会检查奖励。探索、战斗或通行证扣除尚未核实的中断不会提前进入任务页。

## 难度 1 首通

首通任务每次至多出发一次，出发前核对美食殿堂、难度 1 和通行证减少 1 张的预览。已可跳过时不再次出发。有当前探索时接续该进度。默认普通战试打队伍为本体佩可莉姆、可可萝、凯露；要求六星、等级和技能至少 365、Rank 至少 38。普通敌人最高支持 380 级、单体生命值不超过 300 万；开战前逐一读取生命值与机制，特殊机制停止。角色身份和培养由程序读取，公共资料由程序准备；不会升级角色或购买缺少的资源。

任务核对可行动节点、普通战斗、伙伴与事件奖励，商店只退出而不购物。普通战继续使用已核验的初始三人队。难度 1 首领当前只支持暗黑滴水嘴兽的已观察机制；程序盘点伙伴、核对身份与技能后，按公开职能组成最多三队，每名成员要求等级和技能至少 350、Rank 至少 38、至少三星。须保留培养已核验的初始核心，且有至少十名符合要求的伙伴才试打。多队编组、第一队到第二队接战及首领击杀已在雷电 960×540 验证，其他随机伙伴组合仍须通过培养与身份核验，不能保证都能首通。

未知随机事件、未知资源变化、失败、未知页面或超时时停止并保留探索；不会撤退、返回领取部分奖励或重复出发。首领奖励、CLEAR 结果、宝箱、难度解锁和已通关复查已验证；空缓存下从首页一次连续完成新探索，以及未见随机分支仍需验收，见[工程待办](../pending-validation.md)。

```yaml
DawnLabyrinthFirstClear:
  timeout: 1800
  max_battles: 30
  retry_failed_boss: false
```

`timeout` 范围为 1～7200 秒；`max_battles` 为本次战斗次数上限，范围 1～60。`retry_failed_boss` 默认关闭：失败页保留现场；显式启用后，至多进入一次重新编组，重新核对敌人与全部队伍。遇到额外消费确认不会继续。首次伙伴选择中断时，仅在选择编号与数量都能核对时自动清空并重选。

## 消耗通行证扫荡

扫荡沿用游戏内已经选择的难度。在“可跳过的公会一览”清空原有勾选，优先选择已通关的美食殿堂，按预算设置每个公会的通行证使用数量；核对消费前后余额，再独立核对“一键扫荡确认”的公会、次数、消费与当前余额，提交后核对扫荡结果、领奖和实际扣除。尚未解锁时停止并提示先完成首通。有正在进行的探索时先完成该探索。

```yaml
DawnLabyrinth:
  timeout: 600
  max_passes: 99
```

`max_passes` 为本次最多消费的通行证数量，范围 1～99，不超过进入时持有量；`timeout` 范围为 1～3600 秒。数量控件通过 MIN、MAX 和加号自动限制在预算内，预览无法核对时停止。达到上限但仍有通行证时报告 `partial`；确认全部用完且任务奖励处理完成才报告 `complete`。持有量为零时仍检查任务奖励。若领奖增加通行证，记录新余额并留待下次运行，不扩大本次消费预算。

扫荡不改变难度，不探索首通、购买资源、撤退或重置。持有上限、未知界面或消费后缺少回执时保留现场并停止，不重复确认。运行记录中的 `pending_spend` 表示消费已发起、结算尚未核实；`pending_mission_claim` 表示任务奖励领取已发起、回执或领取后状态尚未核实，应先核对游戏结果。重新运行可识别并关闭已存在的任务奖励回执，随后重新检查任务状态。

单张、多张及消耗至零的扫荡已通过正式 CLI 任务实测，已通关首通与零票扫荡重跑不消费。验证范围为雷电 960×540；GUI 实机操作、其他设备、布局与异常结算见[工程待办](../pending-validation.md)。游戏页面与规则见[迷宫知识](../game-knowledge/dawn-labyrinth.md)。
