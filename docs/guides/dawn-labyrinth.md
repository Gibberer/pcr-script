# 黎明界迷宫

任务从冒险页进入迷宫，默认都不加入任务列表；可在 GUI 的“＋ 添加任务”中选择。

| 任务 | GUI 入口 | 用途 |
|---|---|---|
| `dawn_labyrinth` | 每日日常 → 黎明界迷宫 · 扫荡通行证 | 扫荡已通关公会，消耗现有通行证并领取任务奖励。 |
| `dawn_labyrinth_first_clear` | 按需专项 → 黎明界迷宫 · 难度1首通 | 核对或尝试美食殿堂难度 1 首通，每次至多出发一次。 |

也可单独运行：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dawn_labyrinth --config daily_config.yml
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dawn_labyrinth_first_clear --config daily_config.yml
```

适用设备为雷电 960×540。游戏页面和规则见[迷宫知识](../game-knowledge/dawn-labyrinth.md)，其他设备与尚未支持的流程见[工程待办](../pending-validation.md)。

## 通行证扫荡

先在游戏中选好已通关的难度。任务沿用该难度，在可跳过公会中优先选择美食殿堂，核对公会、次数、消费预览和确认页后提交，再核对结果与实际余额。独立公会选择页最多翻查六页寻找美食殿堂，未找到时重新核对备用公会；确认页名称须与所选公会一致。未解锁跳过或仍有探索进行时停止。已有探索须先在游戏中手动完成，再运行扫荡任务。

```yaml
DawnLabyrinth:
  timeout: 600
  max_passes: 99
```

`timeout` 为运行时限，范围 1～3600 秒；`max_passes` 为本次通行证上限，范围 1～99，恢复核对的旧消费也计入该上限，新增消费不超过进入时持有量。消费达到上限或领奖新增通行证后仍有余额时报告 `partial`；确认余额为零且任务奖励处理完毕时报告 `complete`。领奖新增的通行证留到下次运行，不扩大本次预算。零通行证也会检查奖励。

## 难度 1 首通

任务先核对美食殿堂难度 1 是否可跳过。只有目标公会的明确证据才能判定已首通；证据不明时保留页面并停止。已首通时不再次出发，新探索的出发确认消耗 1 张通行证。

游戏允许零票进行无报酬挑战，但此入口暂不执行该模式。重跑时若停在已识别的零票出发确认，程序先取消并返回首页，再核对已有首通；不会将无报酬预览作为扣票首通的依据。零票挑战的结算限制见[游戏规则](../game-knowledge/dawn-labyrinth.md)。

首通入口也会按 `DawnLabyrinth` 的设备／账号配置检查日常待核对记录；存在未核对的扫荡或领奖时，先运行 `dawn_labyrinth` 恢复，不开始首通或再次领奖。首通不会改写日常记录。

新探索先从人物页读取三个核心角色的六个普通装备槽与独立专武状态，两项检查之间自动返回首页，再重新进入并核对同一角色衣装；随后核对通行证、公会与首通状态。未来槽位不计为缺装；培养不足、已开放槽未穿戴、专武未知或证据过期时在出发前停止。招募后只为身份与等级、Rank 一致的自持伙伴复用本次出发前证据，NPC 不继承自持装备。

NPC 及后续伙伴的完整装备读取、首领已验证策略的自动来源尚未支持，新探索仍可能在邀请、替换首领队伍或开战前停止；跨运行也尚不能核验同行公会，因此已有探索会保留现场。已通关检查可用。

试打要求角色身份、技能、全部已开放普通装备槽及专武 1、2 状态均有证据，并满足以下培养条件。攻略明确声明的装备件数继续单独核对，不能用“已开放槽穿满”放宽来源要求：

| 队伍 | 条件 |
|---|---|
| 普通战 | 本体佩可莉姆、可可萝、凯露；六星，等级和技能至少 365，Rank 至少 38。敌人最高 380 级、单体生命值至多 300 万；身份、分类、完整介绍与全部技能须匹配已核对的说明，空白、低置信度、额外条目或可滚动的说明停止。 |
| 最终首领 | 仅支持暗黑滴水嘴兽的已知分类、完整介绍与技能；多页说明须有连续重叠，缺项、新增或低置信度说明停止；保留上述核心，至少十名伙伴，其他成员等级和技能至少 350、Rank 至少 38、至少三星；攻略须有来源和适用条件证据，成员与培养要求逐项核对；通用职能分数不能授权配队。 |

完整配队计划通过后才替换保存的首领队伍。商店只退出；未知事件、资源变化、敌人、页面或超时会停止并保留进度。任务不购买资源、升级角色、撤退或重置探索。

```yaml
DawnLabyrinthFirstClear:
  timeout: 1800
  max_battles: 30
  retry_failed_boss: false
```

`timeout` 范围为 1～7200 秒，`max_battles` 为战斗次数上限，范围 1～60。`retry_failed_boss` 默认关闭；开启后仅在当前探索已核验时允许一次重新编组，并重读敌人与队伍。重试再次失败或出现额外消费确认时停止。

## 领奖与中断

两项任务在结算确认后检查迷宫首页的“任务”角标，进入“全部”读取清晰的任务内容和单项可领取状态，才保存记录并领取奖励；内容缺失或置信度不足时不发起领取。领取后核对回执、按钮禁用和首页角标消失。连续新奖励的后续批次会先返回首页读取实际通行证余额，再重新核对任务内容；前批奖励增加的通行证不会沿用旧数核账。已通关复查、零票扫荡和达到消费上限时也会检查奖励；探索或战斗尚未结算时不进入任务页。

报告中的 `pending_spend` 表示消费计划已保存但提交或结算尚未核实，`pending_mission_claim` 表示奖励领取尚未核实。日常扫荡任务同时将待核对记录保存在 `cache/daily/dawn_labyrinth_state/`，按设备或 `DawnLabyrinth.account_key` 隔离；同一设备切换账号时使用不同的非空 `account_key`。

重跑先核对上一笔扫荡结果及实际通行证余额，已核实的旧消费计入本次上限；回执未知或余额不符时不开始新消费，也不先领取会改变余额的任务奖励。仍停在对应消费确认页时先取消，核对余额未变才解除记录。记录明确证明尚未开始确认提交时，回到首页也可在连续三次新画面中核对入口、无弹窗或连接及余额未变后解除记录，不计耗票；已开始提交或旧记录缺少提交阶段时，余额未变不能单独解除记录。普通报酬确认不能代替扫荡结果。已有领奖记录由领取回执或已清空的任务列表及首页提示核实；若记录保存后尚未实际领取，也可在通行证余额未变、原任务内容与可领取状态经过连续新截图复核后解除旧记录，再领取这些仍未领取的奖励。只有“全部收取”蓝色而缺少原任务内容、列表变化或仍在连接时均保留记录。首通任务仍按当前探索页面核对上下文，不以旧报告授权新探索。记录位置与运行控制见[运行诊断](../run-diagnostics.md)。
