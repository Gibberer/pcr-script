# 黎明界迷宫

任务从冒险页进入迷宫，默认都不加入任务列表；可在 GUI 的“＋ 添加任务”中选择。

| 任务 | GUI 入口 | 用途 |
|---|---|---|
| `dawn_labyrinth` | 每日日常 → 黎明界迷宫 · 扫荡通行证 | 扫荡已通关公会，消耗现有通行证并领取任务奖励。 |
| `dawn_labyrinth_first_clear` | 按需专项 → 黎明界迷宫 · 难度1首通 | 核对或尝试美食殿堂难度 1 首通，每次至多出发一次。 |

也可单独运行：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dawn_labyrinth --config daily_config.yml
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dawn_labyrinth_first_clear --config daily_config.yml
```

适用设备为雷电 960×540。游戏页面和规则见[迷宫知识](../game-knowledge/dawn-labyrinth.md)，其他设备与尚未支持的流程见[工程待办](../pending-validation.md)。

## 通行证扫荡

先在游戏中选好已通关的难度。任务沿用该难度，在可跳过公会中优先选择美食殿堂，核对公会、次数、消费预览和确认页后提交，再核对结果与实际余额。未解锁跳过或仍有探索进行时停止。

```yaml
DawnLabyrinth:
  timeout: 600
  max_passes: 99
```

`timeout` 为运行时限，范围 1～3600 秒；`max_passes` 为本次通行证上限，范围 1～99，实际预算不超过进入时持有量。消费达到上限或领奖新增通行证后仍有余额时报告 `partial`；确认余额为零且任务奖励处理完毕时报告 `complete`。领奖新增的通行证留到下次运行，不扩大本次预算。零通行证也会检查奖励。

## 难度 1 首通

任务先核对美食殿堂难度 1 是否可跳过。只有目标公会的明确证据才能判定已首通；证据不明时保留页面并停止。已首通时不再次出发，新探索的出发确认消耗 1 张通行证。

当前完整普通装备读取尚未支持，新探索会在邀请或开战前停止；跨运行也尚不能核验同行公会，因此已有探索会保留现场。已通关检查可用。

试打要求角色身份、技能、六件普通装备及专武 1、2 状态均有证据，并满足以下培养条件：

| 队伍 | 条件 |
|---|---|
| 普通战 | 本体佩可莉姆、可可萝、凯露；六星，等级和技能至少 365，Rank 至少 38。敌人最高 380 级、单体生命值至多 300 万，特殊机制停止。 |
| 最终首领 | 仅支持暗黑滴水嘴兽的已知机制；保留上述核心，至少十名伙伴，其他成员等级和技能至少 350、Rank 至少 38、至少三星；按职能组成最多三队。 |

完整配队计划通过后才替换保存的首领队伍。商店只退出；未知事件、资源变化、敌人、页面或超时会停止并保留进度。任务不购买资源、升级角色、撤退或重置探索。

```yaml
DawnLabyrinthFirstClear:
  timeout: 1800
  max_battles: 30
  retry_failed_boss: false
```

`timeout` 范围为 1～7200 秒，`max_battles` 为战斗次数上限，范围 1～60。`retry_failed_boss` 默认关闭；开启后仅在当前探索已核验时允许一次重新编组，并重读敌人与队伍。重试再次失败或出现额外消费确认时停止。

## 领奖与中断

两项任务在结算确认后检查迷宫首页的“任务”角标，进入“全部”领取奖励，并核对领取回执、按钮禁用和首页角标消失。已通关复查、零票扫荡和达到消费上限时也会检查奖励；探索或战斗尚未结算时不进入任务页。

报告中的 `pending_spend` 表示消费已发起但结算尚未核实，`pending_mission_claim` 表示奖励领取尚未核实。遇到这些状态，先核对游戏结果与回执；重新运行可接续已存在的任务奖励回执。记录位置与运行控制见[运行诊断](../run-diagnostics.md)。
