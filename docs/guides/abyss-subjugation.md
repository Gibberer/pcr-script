# 深渊讨伐战每日任务

任务名为 `abyss_subjugation`，GUI 的每日日常与通用 CLI 共用实现。程序从国服数据库取得本期活动编号、名称、开始及结束时间，按国服 UTC+8 筛选；进入后再核对游戏显示的名称和时间。不在开放期时跳过。游戏页面与证据范围见[深渊讨伐战知识](../game-knowledge/abyss-subjugation.md)。

任务依据实际通关状态接续，不按登录天数猜测：首次用同一个五人队伍通过三种前哨难度，再扫荡各难度剩余机会；每日取得挑战券后，从低到高逐档补齐三个首领的首通。全部三个首领的普通、困难、高难、极难均确认通关后，将剩余券用于任意一个极难首领，默认选地图最左侧。高难首通后极难会新增到难度列表顶部，程序按实际文字定位并滚动核对。第二天仍有未通关首领就继续首通，第三天也不会把尚未通关误判为可扫荡。

## 运行与配置

新工程的默认日常已包含本任务。已有配置可在 GUI 添加“深渊讨伐战”，或在 `Task` 列表加入 `[abyss_subjugation]`。单独执行：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py abyss_subjugation --config daily_config.yml
```

配置段为 `AbyssSubjugation`；省略字段使用根目录 [runtime_defaults.yml](../../runtime_defaults.yml)：

```yaml
AbyssSubjugation:
  discover_sources: true
  source_urls: []
  timeout: 7200
  battle_timeout: 240
  max_stamina: 400
  max_boss_tickets: 99
  max_normal_trials: 6
  max_simulations: 30
  max_source_batches: 3
  auto_equip_special: true
  allow_five_star_upgrade: false
  allow_divine_amulets: false
  preview_only: false
  allow_local_trials: true
  auto_collect_house_stamina: true
  normal_team: [1, 1]
  boss_teams: [[1, 1], [1, 2], [2, 1], [2, 2], [3, 1], [3, 2], [4, 1], [4, 2], [5, 1], [5, 2]]
```

程序优先自行搜索和解析本期国服高难前哨攻略，核对发布时间、年月、属性及画面中的难度。`source_urls` 可指定公开链接，仍需通过同样核验；不要求 Agent 准备队伍文件。五人身份和固定 SET/AUTO 必须有多帧证据，未支持的手动轴、借角、全局培养或特别装备要求会阻止采用。来源培养缺项时，`allow_local_trials: true` 允许逐人核验账号培养后试打；已明确的 Rank、星数、专武等要求仍须符合，账号现状不会补写为攻略要求。

取得适用攻略后先盘点本期属性的候选角色，按已观察的持有情况和培养差距排序；先核验各批原阵容，再尝试有依据的缺员替补。来源相同候选不会无限重复，最多检索 `max_source_batches` 批，每批仍受视频数和解析时间限制。未取得可执行候选时核验游戏当前编组，再检查 `normal_team` 和 `boss_teams`。两个数字是游戏“我的队伍”中的编组与顶部队伍位置，默认编组 1 的第一队；当前支持编组 1～5 中顶部两个完整可见的保存队伍。选定后前哨各难度复用同一队，后续运行保留身份候选并重新核验。若明确失败且次数和券均未扣除，可核验下一份攻略或其他保存队伍；每难度最多 `max_normal_trials` 次，本日已失败的五人阵容不再试打。设为 1 可限定每难度只试一次。

搜索、视频解析和头像准备复用现有共享链路；选人、账号试打、培养差距和战前准备与深域共用同一模块，见[公共准备流程](../party-preparation.md)。程序核验实际五人、衣装、等级、Rank、星数和专武 1/2；身份、属性或装备未知时不能开战。身份可由已确认头像或普通技能核实。攻略明确要求的技能等级另行读取；来源缺失的技能培养字段保留为未知，沿用深域的当前账号试打规则。近期审计在确认实际五人、装备徽标和原要求一致后复用，过期后重新读取。首领优先解析同一首领极难攻略，默认每批首领来源最多解析 5 分钟，可用 `sources.parse_timeout` 调整；随后核验前哨队伍、当前编组和保存队伍。券耗尽后下次接续。历史跳过伤害本身不视为首通，须结合扫荡可用、后续难度解锁或已核账的实战胜利；所有难度均确认首通后才集中扫荡极难。攻略试打保留来源的固定 AUTO 和每人 SET；游戏保存队伍固定 AUTO 开启、五人 SET 开启。报告分别记录来源缺项、账号培养及试打依据。程序不调用支援。`auto_equip_special: true` 会在试打前用游戏自动装备分配现有特别装备，可能从其他角色调装备；关闭时仍只读检查。模拟达标后的实战只核对同一配装，装备或五人变化会停止扣券，须重新模拟。

首领免费模拟须确认击杀，或确认队伍存活至时限且伤害达到同一视频方案的参考值。来源分 P 的明确伤害及“一刀／几刀”与已核验的首领、难度绑定；刀数须有该来源的生命上限才能换算。较低难度的参考伤害最高取当前首领生命上限，此时必须模拟击杀。没有参考值的队伍须先模拟击杀，正数伤害本身不能授权实战。持续减员直接复用深域的撤退、一次有依据的免费重试及生存换队判断；输出不达标则按公共流程调整输出候选，同一失败阵容不原样反复试打。实战后用已核账的生命值差核对伤害，减员或低于模拟／攻略预期时先重新配队和模拟，不能连续投入挑战券。

`allow_local_trials: false` 可限制为已通关关卡的扫荡。`preview_only: true` 只核对活动及余额，不开始新战斗、领取体力或提交扫荡；已有待核对消费仍先恢复。`max_stamina` 和 `max_boss_tickets` 是本次合计消费上限，实际还受持有资源、游戏次数及活动结束时间限制；不是每日购买额度。体力不足时最多领取一次公会之家已有产物，再重读详情。任务不购买体力、不重置次数或首领进度、不训练专武。

来源优先核对同名首领的最高“极难”。`allow_local_trials: true` 时，同一来源可用于较低难度的账号试打。报告保留来源难度与适配假设，游戏关卡仍按当前普通／困难／高难／极难核对，先核验实际五人并免费模拟，再决定实战。来源的服区、固定 SET/AUTO、明确培养和装备要求仍须满足；不同首领或未知全局要求不能采用。

攻略原阵容候选用尽后，缺员替补复用公共的同属性、同攻击类型及职能筛选。报告保留原攻略名单、替补依据和当前账号培养；替补不会继承缺失角色的培养要求，保留的原成员仍须满足来源已明确的要求。实际五人重新核验并免费模拟后才能实战。

已核验的本地队伍在新进程中仅因专武状态未知而无法复用时，程序重新检查人物页并保留此前的培养要求；不会把未知徽标当作专武未开启。角色、星数、Rank 或已知装备不符仍会阻止开战。

`allow_five_star_upgrade` 默认关闭；显式开启后，符合条件的拟上场角色可复用五星培养，`allow_divine_amulets` 独立控制碎片兑换。来源明确要求三星、四星时保持该目标；其他培养不符会先阻止消费。培养后重新编队并保留 AUTO/SET，不把培养前的模拟结果继续用于实战。

报告的 `party_audits[].cultivation` 列出等级、Rank、星数、技能、专武 1/2 的具体差距，区分补装与强化。来源明确“专武 1 等级 310”或“专武 2 五阶段”时只确认安装不算达标。专武补装及强化、按攻略定向的普通培养目前没有完整的消费执行器，会拒绝不满足要求的候选；独立任务“强化所有角色”不作为战前自动补救。不能把账号当前没有专武 2 自动视为攻略也不需要。

## 结果与中断恢复

报告、编队核验与消费前后证据保存在忽略目录 `cache/daily/runs/<run>/tasks/<序号>-abyss_subjugation/`。`complete` 仅表示本次所有前哨机会和持有挑战券均已核对使用完；券不足时首领可能仍未全部首通，另看 `all_bosses_cleared` 和 `bosses`。`partial`、`blocked` 保留未完成原因，不表示全部通关。

提交前持久化待核对记录，前哨以实际次数减少及券增加确认，首领以券扣除和通关状态／血量进展确认。回执丢失时先核账，不重复提交。仍停在未提交的扫荡确认页时先取消，余额一致才解除记录；跨国服 05:00 的未核对前哨消费不能仅凭刷新后的次数解除。旧版首领通关缓存会由当前游戏页面重新核验，深蓝色禁用扫荡按钮不能授权跳过首通。

记录位于 `cache/daily/abyss_subjugation_state/`，按设备或 `account_key` 与活动编号隔离。切换账号时设置不同的 `account_key`，同一账号保持不变。运行中检查设备前必须等暂停确认，见[运行诊断](../run-diagnostics.md)。空缓存和其他布局的验收范围见[工程待办](../pending-validation.md)。
