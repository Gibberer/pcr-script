# 深渊讨伐战每日任务

任务名为 `abyss_subjugation`，GUI 的每日日常与通用 CLI 共用实现。程序从国服数据库取得本期活动编号、名称和开放时间，按国服 UTC+8 筛选，再核对游戏画面；不在开放期时跳过。游戏机制及实测范围见[深渊讨伐战知识](../game-knowledge/abyss-subjugation.md)。

任务从本期适用攻略产生候选，结合账号持有角色与培养选择可执行方案。新战斗必须有来源；攻略缺失或全部候选不合格时保留资源并报告原因。游戏当前编组、保存队伍位置及旧运行的账号快照不会独立成为候选。搜索、头像准备、解析和缓存刷新由程序完成，不要求 Agent 提供队伍文件。

## 运行与配置

新工程的默认日常包含本任务，并放在第一次快捷扫荡之前。已有配置可在 GUI 添加“深渊讨伐战”，或在 `Task` 中第一次 `[quick_clean, ...]` 之前加入 `[abyss_subjugation]`；活动前哨优先使用体力，快捷扫荡负责清理剩余体力。单独执行或补跑未完成部分：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py abyss_subjugation --config daily_config.yml
```

省略字段使用根目录 [runtime_defaults.yml](../../runtime_defaults.yml)：

```yaml
AbyssSubjugation:
  first_clear: true
  discover_sources: true
  source_urls: []
  timeout: 7200
  battle_timeout: 240
  max_stamina: 400
  max_boss_tickets: 99
  boss_max_attacks:
    普通: 1
    困难: 1
    高难: 2
    极难: 6
  max_normal_trials: 6
  max_simulations: 30
  max_source_batches: 3
  allow_local_trials: true
  allow_five_star_upgrade: false
  allow_divine_amulets: false
  on_demand_cultivation: true
  auto_collect_house_stamina: true
  preview_only: false
```

日常默认包含三个首领各难度的首通，以取得首通奖励；保留 `first_clear: true`，程序先补齐首通，再用剩余委托证扫荡极难。只有明确希望仅扫荡已通关关卡时才设为 `false`；关闭后不开始新首通或首领模拟。

`allow_local_trials` 只控制已有攻略的账号适配：补核缺失的培养字段、缺员替补、同一目标最高难度攻略用于较低难度，以及同一首领低难度阵容用于较高难度免费模拟。跨难度保留来源真实标签，清除原攻略伤害参考；在当前目标免费模拟后，按下述伤害与刀数条件决定是否实战。关闭它仍可执行当前难度培养要求完整的攻略，不等于关闭首通。

旧配置中的 `normal_team`、`boss_teams` 已停用，GUI 与执行入口共用迁移并移除保存位置。任何未指定 `first_clear` 且设有 `allow_local_trials: false` 的配置都保留旧版“只扫荡”意图，补入 `first_clear: false`，包括没有保存位置的手工配置。若希望只采用完整攻略首通，明确设置 `first_clear: true`、`allow_local_trials: false`。

## 选队与培养

前哨可保留来源已确认的混属性阵容；首领仍按本期加成属性核验。程序按当前前哨或首领的实际难度取得来源，核对本期、服区、首领、五人衣装及固定 SET/AUTO；未支持的手动轴、借角、必需的全局培养或特别装备条件会阻止直接采用。开启 `allow_local_trials` 时，首领攻略若只因手动操作或借角不能照搬，仍取其五人阵容，排在可照搬的攻略之后：能确认固定开关的沿用，途中切换或未读到的按 SET、AUTO 开启，在当前目标免费模拟，通过才实战；作者评论含未解析图片或来源未读到固定 SET 时同样走这条路径；全程只显示练度表的视频也可读出五人和表内固定 SET，表内等级、Rank 只算作者练度；未注明难度的分 P 也可由标题的首领名或序号（如“1王”）绑定，同样只作试打。必需的全局培养或特别装备条件仍然拒绝，前哨不采用这条路径。作者明确标注的参考练度保留为建议，账号实际能否使用仍由培养核验和免费模拟判断。`source_urls` 可指定公开链接，但仍通过相同核验。每批来源的解析时限可用 `sources.parse_timeout` 调整，任务总时限由 `timeout` 控制。

攻略视频默认至少使用720p清晰度，避免低清版本中角色SET按钮文字无法辨识；下载和解析期间显示当前批次耗时。每个视频默认最多检查 12 个分 P、每页 96 帧，超出预算仍拒绝未完整读取的来源。开启 `allow_local_trials` 时，战斗中的首领名称、等级与生命上限可与当前详情对应，保留账号试打标记；短战斗会在首次读到完整五人后就近复核。来源仅出现借角确认界面时，可改用本账号持有的五人免费模拟；明确要求借角的攻略仍不采用。

可在 `sources.search_queries` 中补充关键词，例如 `['公主连结 深渊讨伐战 全自动']`；程序仍使用任务默认查询，并对全部结果核验本期和目标。作者明确写出的五位 `O/X` 可表示固定 SET 顺序：`O` 开、`X` 关；须对应当前首领与视频中的五人，不能覆盖相反画面，也不能把途中切换的手动轴视为固定设置。

每个目标有独立的有界候选流程：按已观察的持有情况和培养差距排序，先核验各批攻略原阵容，再在允许账号适配时尝试有依据的缺员替补。每个目标至多检索 `max_source_batches` 批；失败后继续尚未尝试的候选，不重开搜索预算。公开来源缓存按当前目标及解析器版本重新核验，旧账号队伍快照不恢复为开战依据。

来源未声明培养要求时，程序按头像选入五人后直接以实战（前哨，失败不扣资源）或免费模拟（首领）的结果判断，不逐人读取等级、技能和专武，`party_audits` 中标记为 `portrait_trial`。来源明确的 Rank、星数、技能和专武要求必须满足，此时走完整核验：只有缺失字段才绑定账号观察，报告保留缺项与适配假设；五人身份、属性和专武状态未知时停止。完整攻略队伍与账号适配队伍在模拟后都固定已核验的培养要求，不能在实战前以新的账号状态覆盖要求。同一次运行中，前哨已解析到可用队伍后，其他难度直接复用该解析结果。选人、培养差距与战前装备复用[公共准备流程](../party-preparation.md)。

试打前总是按游戏自动装备分配现有特别装备，可能从其他角色调装备；这不是可关闭的选项，旧配置里的 `auto_equip_special` 会被忽略。首领实战前须核对与模拟时相同的五人及配装，变化后不能沿用模拟授权。

`on_demand_cultivation` 默认开启：实测未达标时，对上场成员按需升到五星并补齐空专武，确有变化就用同一攻略重测；每名角色每次运行只处理一次。专武 1 缺记忆碎片时会消耗女神的秘石买到 50 个（当期观察约每个 4 秘石）；专武 2 素材不足时放弃，列在报告的 `needs_user` 里由你处理。不强化已有专武，也不使用专用装备辉光球；报告见 `on_demand_cultivation`、`star_upgrades`、`unique_installs`。全员等级、装备和品级由日常的 `upgrade_all_characters` 负责，标准见[公共准备流程](../party-preparation.md#能力边界)。`allow_five_star_upgrade` 默认关闭，开启后在实测前就培养拟上场且允许升到五星的成员；`allow_divine_amulets` 独立控制碎片兑换。报告的 `party_audits[].cultivation` 区分检查、补装和强化。

## 首通、模拟与资源

前哨已通关且全部剩余次数符合当前体力与本次预算时，优先使用首页“一键扫荡”。程序核对各档次数、汇总数量及体力，再核对第二层消费确认；结算后逐档核账。部分尚未首通、选择次数不完整或资源预算不足时，按实际通关状态逐档首通和扫荡。明确失败且次数、券均未扣除时，可继续下一份攻略；每难度最多 `max_normal_trials` 次。本日失败记录包括五人、培养、SET/AUTO 和伤害依据，设置不同的来源方案不会仅因同样五人就被跳过。

先依次核对三个首领的普通、困难、高难，再处理三个首领的极难。默认每个首领的普通、困难各以 1 刀首通，高难最多 2 刀，极难最多 6 刀。极难通常需要 4～6 刀的使用经验见[游戏知识](../game-knowledge/abyss-subjugation.md)；刀数是规划上限，不是通关保证，可在 `boss_max_attacks` 中逐难度调整。

每支队伍先免费模拟，减员也打满到结算，不提前撤退。确认击杀即可采用；未击杀时，须正常结算，再以账号本次模拟伤害估算 `向上取整(当前剩余生命 / 模拟伤害)`，减员本身不影响判定。预计刀数不超过该首领剩余预算才实战。满血普通、困难的一刀方案仍须模拟击杀；已有实战进度的尾刀按实际剩余血量判断，不要求再次模拟击杀满血首领。来源阵容与替补采用相同验收条件，账号伤害单独记录，不改写为攻略参考值。

每刀后核对实际扣券和剩余生命，再判断是否能在剩余刀数内完成。首领实战同样打满；伤害低于 `向上取整(本刀前剩余生命 / 本刀前剩余刀数)`，先换队重新模拟，不继续沿用原队扣券。模拟未通过且减员时，只允许公共重试判断支持的一次免费重试。已消费刀数按账号、本期、首领和难度持久化，中断、换队或次日重跑不会重置上限；达到上限保留游戏进度并报告。实际出刀仍受持有券及 `max_boss_tickets` 限制，券不足时保留未完成进度。

某首领的攻略候选用尽后保留未完成原因，继续核对其他独立首领；三个首领的普通、困难和高难全部确认首通后才进入极难，避免未完成高难时转去消耗极难的搜索和挑战预算。待核对消费、未知战斗结果或页面异常仍会停止整个流程；未全部首通时不会用极难扫荡代替。

全部首领各难度确认首通后，剩余券扫荡一个极难首领，默认选最左侧。本账号、本期已有前三档完整首通记录时，后续直接核对三个极难详情，接续未完成首通或全部首通后扫荡，不再逐档打开低难度；当前页面与记录冲突时停止。第二天根据当前进度接续，不按登录天数推断已通关。历史伤害本身不证明首通，须结合扫荡可用、后续难度解锁或已核账胜利。

`max_stamina` 和 `max_boss_tickets` 是本次合计消费上限，还受持有资源、游戏次数及活动结束时间限制。体力不足时可领取一次公会之家已有产物，再重读余额。任务不购买体力、不重置次数或首领进度、不强化已有专武。`preview_only: true` 只观察，不开始新战斗、领取体力或提交扫荡；已有待核对消费仍先恢复。

## 结果与中断恢复

报告与证据位于忽略目录 `cache/daily/runs/<run>/tasks/<序号>-abyss_subjugation/`。`complete` 表示本次前哨机会和持有挑战券已核对使用完；首领是否全部首通另看 `all_bosses_cleared`。`partial`、`blocked` 保留未完成原因，不代表全部通关。

消费前持久化待核对记录，前哨以次数减少及券增加确认，批量扫荡还核对三档数量与委托证总增加量；首领以券扣除和通关／血量进展确认，并处理“扫荡结果”和“首领结算”两段回执。回执丢失先核账，不重放。未提交的扫荡确认页先取消，余额一致才解除记录；跨国服 05:00 的未核对前哨消费不能仅凭刷新后的次数解除。旧运行的消费记录继续核账，账号编组缓存不恢复。

状态位于 `cache/daily/abyss_subjugation_state/`，按设备或 `account_key` 与活动编号隔离；切换账号设置不同的 `account_key`。设备接管须等暂停确认，见[运行诊断](../run-diagnostics.md)。冷缓存和真实连续战斗的验收缺口见[工程待办](../pending-validation.md)。
