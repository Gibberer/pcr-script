# 任务使用指南

GUI 的“每日日常”会按顺序执行预设列表；配置好 Python 依赖和设备后即可点击“开始今日日常”。“按需专项”每次只处理一个目标。两者使用同一份 Python 任务实现与运行记录。首次设置见 [GUI 指南](desktop.md)。

## 一、日常任务

完整日常进入游戏首页最多等待 10 分钟，供雷电与游戏首次启动、加载和登录使用；确认首页后立即继续任务。超过上限仍未进入首页会报错停止。

新工程从 `runtime_defaults.yml` 加载一组现成的日常任务，无需逐项添加。需要自定义时，选中任务修改参数、启用状态或顺序，也可以点“＋ 添加任务”扩充列表。相同任务可以出现多次，例如扫荡前后分别领取首页任务奖励。

有两次快捷扫荡时，前面的首页任务领奖用于领取体力，最后一次扫荡及其他日常结束后再安排一次 `get_quest_reward`，收取后续操作新达成的奖励。

编排时将复刻、剧情活动、深渊讨伐等时限任务放在第一次快捷扫荡（`quick_clean`）之前；快捷扫荡用于消耗剩余体力。时限任务受阻时，先查看未完成原因并单独接续，确认不再需要保留体力后再清体力。当前完整日常会继续执行后续项，列表顺序本身不保证失败后仍保留资源。

默认执行顺序见 [runtime_defaults.yml](../../runtime_defaults.yml)，更多参数写法见 [daily.example.yml](examples/daily.example.yml)。GUI 中主动选择“新建配置”会得到空白列表，供自行编排；默认列表不包含地下城、深域或角色培养。需要首页的任务由统一调度返回首页，不必穿插 `tohomepage`；不能识别的弹窗保留现场。

命令行和 GUI 默认先查找 `daily_config.yml`，没有时使用根目录 `runtime_defaults.yml`；也可指定自己的 YAML。完整日常运行 `daily_task.py --config <配置文件>`，脚本按所选文件的 `Task` 列表执行。GUI 编辑第一个任务组，保留已有账号与其他组，但不提供账号登录或多组切换。

## 二、单项与专项任务

在“按需专项”选择任务，阅读起始页面和消费范围，调整“本次运行选项”，点击“执行本次专项”。这些选项不会写回日常配置。日常列表中的项目也可用右侧“单独执行选中项”执行一次。

命令行通用形式：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py <注册名> --config daily_config.yml
```

有位置参数时使用 `--args` JSON 数组；任务配置段仍来自 YAML。

团队战任务的定位是 A/B/C 阶段的“一队两刀”：阵容远超首领要求，一支推荐队伍普通击杀一个首领后，用返还时间延长击杀下一个，通常第一批候选就能通过。因此普通挑战只接受击杀，不接受仅达到参考伤害的队伍；同一首领连续 `TeamBattle.max_boss_failures`（默认 3，0 为不限）支队伍模拟未通过时，即按超出低难度前提处理，改试其他首领并在报告中说明。找不到击杀队伍时，报告提示优先排查识别或页面异常；D 阶段起首领需要精确配队与伤害规划，本任务不处理。

团队战需要只验证模拟战时，在本次使用的 YAML 的 `TeamBattle` 段设置 `simulation_only: true`。任务按实战规则做模拟预演：最多 `max_real_attacks` 刀，每刀查找能击杀且满足双刀预算的新队伍，通过后视为已参战，下一刀不再使用其成员；首领血量不变，因此每刀都按同一首领核对。报告的 `rehearsal` 列出各刀队伍与返还时间，不进入实战编队、不消耗挑战次数；常规日常不设置此项。单独运行时若游戏停在标题画面，任务会先登录回到首页再进入团队战。

团队战准备战斗时核对详情中的阶段：第1～3阶段（A/B/C）可继续，第4阶段起或阶段无法确认时停止。任务不修改「隐藏角色」筛选，直接翻查默认高级推荐，含已参战或缺员成员的队伍在列表或编队页跳过。

免费模拟的搜索轮数不代表游戏挑战次数。`TeamBattle.max_simulations: 0` 为默认值，表示不限制模拟轮数，仍受 `timeout` 总运行时限及 `battle_timeout` 单场超时约束；重复的同一队伍在同一目标条件下不会反复试验。已有配置若显式设置12等正整数，仍保留该程序搜索上限；可设为0继续搜索更多候选。达到程序上限报告搜索受限，不当作游戏次数耗尽或没有可用队伍。

团队战按五个已选头像核对人数、队伍占用和模拟／实战编队的一致性；报告中的角色名仅作辅助，漏读时可以留空，不代表缺员。普通模拟编队出现「已参加团队战」或「限制实战使用」时即跳过该队，不先做无效模拟。使用推荐后若编队仍被拒绝，运行日志记录原因，并保存当时的编队截图供核对。普通实战明确提示「编组成员不足5名角色。」且实际缺员，或五槽全空且总战力为 0 时，取消编队并跳过该队伍；其他不明的编队变化仍停止开战。

普通挑战击杀后的延长挑战优先模拟同一首领的下一可见轮次；目标不可用或模拟未通过才尝试其他首领。上一刀目标保存在本地，按设备（可用 `TeamBattle.account_key` 区分账号）、活动期和国服每日 05:00 刷新周期隔离，重启后仍保留此优先顺序。该记录只影响目标排序，不代替当前队伍、剩余时间和模拟结果核验。

满血首领的普通刀先按模拟结算的返还时间检查双刀预算：返还包含20秒奖励，估计首刀耗时为 `90+20−返还时间`，再预留8秒；不足以在返还时间内再击杀一次就换队，不提交第一刀。延长刀仍须在游戏实际返还时限内模拟击杀，不能用电脑端加载、演出和识别的总耗时替代游戏战斗计时；可核实血量的残血首领也纳入延长目标。

满血普通刀必须模拟击杀；只达到参考伤害但未击杀时继续换队模拟，不能绕过双刀预算。每次实战同时核对普通和延长两项次数；任一项与已确认战果不符时保留待核账结果并停止，不重复提交战斗。

已有延长刀需更换阵容时，可启用 `TeamBattle.rebuild_extension: true`（默认关闭）。任务从高级推荐中重新选择未受实战限制的五人，明确选择延长时间并取消自动编入旧队；模拟和实战都保留该推荐阵容，重新核对五头像、特别装备及返还时限。模拟不击杀则换下一候选，不消耗普通次数；预算内没有可验证方案时保留次数并报告原因。此选项不放宽新普通刀的双刀预算。

### 地下城与深域的来源处理

优先链接分别填写 `Dungeon.source_urls`、`Abyss.source_urls`，不跨任务共享。没有完整方案时自动搜索、获取视频、建立公共头像索引并解析已支持的布局。逐字段保存来源、截图与时间点；未知专武状态不变成“未开启”。开战前仍核对本地角色，不用账号当前培养补写来源缺失要求。

打开 `prepare_only` 可只获取并解析来源，深域需指定 `sources.stage` 和 `sources.element`。当前视频解析、多刀地下城规划和全局培养核验仍有待办，不能保证生成每个关卡的完整作业；见[解析范围](../video-strategies.md)。无法确认时可查看报告与证据，再决定是否调整来源。

`allow_local_trials` 明确允许按当前账号进行试验，默认关闭；试验结果不代表复现源作业。深域五星升级与秘石兑换另有独立开关，默认关闭；不自动购买体力、重置次数或投入专武资源。

### 如何判断结果

每日结束会汇总任务状态与未完成原因。`partial` 表示只完成一部分，`blocked` 表示前置条件未确认，`finished` 表示执行结束但缺少业务核验；进程退出或胜利动画不等于全部目标完成。任务领奖完成也只表示已达成奖励已领取，游戏日课完成数仍以任务页为准。在运行记录查看具体回执和截图。停止/暂停需等状态确认，未确认时不并行启动另一进程操作同一模拟器。排查见[运行诊断](../run-diagnostics.md)。
