# 露娜之塔

改版后的游戏入口为 **冒险 → 特别关卡 → 露娜之塔**。按需专项 `luna_tower_climb` 推进普通楼层；旧日常 `luna_tower_clean` 检查当前区域是否有回廊。本期区域没有回廊时报告不可用，不再执行旧版固定坐标扫荡，也不会把多年静态排期解释为旧限时回廊开放。

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py luna_tower_climb --config daily_config.yml
```

GUI 选择“露娜塔 · 普通楼层推进”，通过 `LunaTower` 配置控制范围。爬塔不自动加入默认日常列表；塔顶按天磨血时可把 `luna_tower_climb` 加入自己的日常。

```yaml
LunaTower:
  target_floor: 0        # 0为当前主库最高层；也可指定普通楼层
  max_floors: 10         # 本次最多推进的普通楼层数
  max_candidates: 20    # 每层最多核对的已识别推荐队伍
  max_pages: 12          # 推荐列表翻页上限
  timeout: 3600
  battle_timeout: 240
  preview_only: false    # 只核对入口、当前楼层与配置，不开战
  simulation_only: false # 普通层模拟获胜、塔顶阶段目标通过后结束，不实战
  auto_equip: false      # 是否为模拟调配已有特别装备，不购买或强化
  free_recovery: true    # 实战已消耗角色时，可使用每天一次免费角色全回复
  video_guides: true     # 塔顶候选读取国服练度表视频
  top_attacks_per_run: 1 # 塔顶每次最多实战的刀数，0为不限制
  top_trials_per_run: 6  # 塔顶每次最多试打的队数，0为不限制
```

任务读取当前楼层的游戏内通关队伍，只接受已确认的自动／立即发动方式。确认预览五人齐全、实际五人头像和顺序与来源一致后，直接免费模拟；默认不逐人打开等级、技能、Rank和专武页面。模拟使用本账号当前状态，来源玩家的培养不作为本账号培养。头像和静态资料由程序自行准备；公共姓名未识别时，按已匹配的五个位置设置SET，不猜测角色身份。

普通塔顶按阶段接续累计削血。候选顺序为：实战证实过削血的队伍、国服练度表视频的非 EX 分P（磨血分P优先）、结构化公开攻略（通过跨服角色ID或公共头像识别衣装）、游戏内通关分队。首领会回血，打不动时多数队伍结算血量反而更高，这些队不会实战；只有一队能净削血时每天打一刀属于正常进度。清影子阶段既接受免伤解除后的持续有效伤害，也识别末段完整可见血条的持续净削血；遮挡的血条不算阵亡。削血阶段核对末段生命，避免把回血前的临时伤害当作进展。阶段模拟完整结算后，同队实战还须确认影子消失或敌方生命减少；只有塔顶出现实战通关标记才算完成。该路径的国服验收边界见工程待办。

每层实战前必须通过模拟，返回后确认目标敌方生命、五人头像及顺序、起始生命／技能值与模拟相同，并采用相同AUTO／SET；变化时停止。普通楼层在同一进程内衔接；塔顶阶段证明只在本次运行内有效，重新运行会先再次免费模拟，防止其他任务调动特别装备后用未测试的配装实战。默认不更换装备、不培养角色。显式开启 `auto_equip` 才会调配已有特别装备；塔顶直接调配，不逐人核验培养属性。塔顶实战消耗角色后可使用每日免费角色全回复，保留敌方进度，清除旧模拟证明后重新模拟；设 `free_recovery: false` 可保留这次免费机会。任务不购买体力、不重置首领或挑战次数、不培养专武。特别挑战的三队路线不属于普通爬塔任务，未知页面不会按普通楼层执行。


实战提交前记录待核账状态，胜利后还须确认实际楼层推进或目标层通关标记。中断后先核对原实战；没有结算证据时保持停止，不重复开战。设备上切换账号时应设置独立的 `LunaTower.account_key`；状态保存于忽略的 `cache/daily/tower_state/`，每次报告与截图保存在运行目录中。

达到楼层、候选或时间预算会报告未完成及原因，可按实际进度接续。实机、冷缓存与特殊结算的验证范围见[工程待办](../pending-validation.md)，当前页面和规则见[游戏知识](../game-knowledge/luna-tower.md)。
