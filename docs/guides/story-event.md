# 剧情活动与复刻活动

GUI 统一使用“活动日常”（`campaign_clean`），通过 `Activities.types` 选择 `story` 和 `revival`，详见[活动日常](activities.md)。`StoryEvent`、`RevivalEvent` 配置段继续兼容。以下旧命令仍可使用；`--only` 单步骤只处理剧情活动：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/story_event.py
./.venv/Scripts/python.exe -X utf8 scripts/daily/revival_event.py
```

## 剧情活动日常

`story` 类型默认处理已通关关卡的困难批量扫荡、可选普通扫荡、可领奖剧情与活动任务、活动券兑换。首通及未通首领默认关闭；首通需准备保存队伍并设置体力上限，高难首领另须核对本期来源和队伍条件。困难批量扫荡体力不足时，默认尝试领取一次公会之家已产出的免费体力，核对到账后重新读取关卡次数与消费预览；可用 `collect_house_stamina: false` 关闭。仍不足时停止追加扫荡，继续处理可领奖内容；不会购买体力或重置次数。

配置示例：

```yaml
StoryEvent:
  first_clear: false
  bosses: false
  stories: true
  memoirs: true
  missions: true
  exchange: true
Task:
  1:
    - [campaign_clean, true, false]
```

任务的两个位置参数分别控制困难扫荡与剩余体力的普通扫荡。需要单独处理一项时，可为独立入口指定 `--only stories|memoirs|missions|sweep|exchange`。游戏页面与当期关卡规则见[剧情活动知识](../game-knowledge/story-events.md)。

启用 `StoryEvent.first_clear` 并明确设置 `allow_local_trials: true` 后，列表式活动首通使用游戏内「自动推进」：核对保存的五人身份和装备，读取推进终点与最高体力消耗，确认「立即发动」后开始。`max_first_clear_stamina` 默认 200，限制本次任务的首通体力；`first_clear_timeout` 默认 900 秒，限制每段自动推进等待。体力不足、队伍未知、进度未增加或非预期中断会停止，不购买体力。首通结束重新扫描关卡与终点，已通关时跳过。

首通预算按结算回执的实际消耗累计。期间回体不抵扣已消费预算；余额比「战前余额减去回执消费」多出的部分单独记录为推算回体量，不推断恢复原因。余额低于该预期时停止追加挑战。

memoirs 控制已适配的附加剧情，包括「复制世界回忆录」及「小沙月敬启」特别章节。首次教学和登录奖励先于首页识别处理。首领仍由 `bosses` 独立控制；启用时先处理已开启的剧情步骤，再检查首领，便于接续剧情解锁。活动情报落后时，程序可从当前活动首页核对举办时间，并将首页艺术字标题与帮助页普通字体标题交叉核对，再按当前难度和模式搜索来源。游戏分行显示的主标题、副标题经帮助页核对后可分别用于检索；标题中的空格不改变活动身份。自动执行按当前难度优先搜索SP或SP＋作业，跳过明确要求手动操作和超出视频时长预算的分P；分析用途的 `prepare_only` 保留完整解析能力。

启用首领后，默认 `require_source_settings: true`、`allow_party_variants: false`：使用本期来源原阵容，核验服区、难度、模式、五人 SET 和固定 AUTO。来源未列出培养要求时，按搜索结果的精确头像选入五人后以当前账号试打，不逐人读取等级、Rank、星数、技能及专武；头像不明确时退回逐人核验。来源列出的培养要求仍逐项核验。不自动替补或养成。无法核验时报告未完成，不将跳过首领记为通关。

活动攻略默认要求至少720p媒体，低清缓存由程序自行替换；只提供更低清晰度的来源会被拒绝。`sources.minimum_media_quality` 可设16、32、64，分别对应360p、480p、720p，默认64；`sources.max_download_seconds` 限制每段总下载时间，默认600秒。提高时间预算不会降低来源、模式或开关核验标准。

合集会跳过明确的抽卡、序幕及第几话剧情分P；标题同时包含攻略、培养要求或说明时仍保留核验，未知标题不据此跳过。宽屏媒体按源视频比例核对相应清晰度档位的长短边，不将短边不足720的宽屏720p误判为360p；服务端降低档位和实际分辨率不足仍拒绝。

找到符合本期难度、模式及开关条件的方案后，先核验账号阵容；缺角或培养不满足时排除该来源，在同一 `sources.max_videos` 候选总预算内继续搜索，不重新尝试已排除来源，也不自动扩大预算。默认每个难度／模式最多4个候选。

跨运行接续时，可在 `StoryEvent.sources.exclude_sources` 中列出已确认不适用的来源URL；程序会与本次运行已排除的来源合并，跳过其搜索与解析。此列表不会自动判断账号培养变化后的方案是否重新可用，需按实际条件维护。

普通特别战斗可显式设置 `allow_phase_continuation_trials: true`，并同时启用 `allow_local_trials`，尝试从已保留的后续模式接续同一来源阵容。仅接受国服、原五人、固定SET/AUTO且无未支持条件的来源；目标阶段须在该队伍连续战斗中有至少两帧高置信度证明。报告保留来源起始模式，并明确记录重新开战的起始TP与来源连续战斗不同，不将其标成已验证的独立模式攻略。同一接续候选最多三次，仍受任务总尝试预算和无进度停止限制；特别战斗＋不适用此选项。

特别战斗＋须另外显式开启 `allow_limited_phase_continuation_trials: true` 才允许上述同难度接续试打，默认关闭。仍要求目标阶段的多帧证明、固定开关、原五人及全部已知培养条件；不能把普通特别方案转为特别＋方案。每个接续候选最多三次，提交前逐次读取实际剩余挑战次数；用尽或无进度时停止，不重置进度或扩大次数。此选项保留起始TP差异，不能视为已验证的独立残局攻略。

单独选择 GUI 的「剧情活动首通」或执行 `scripts/daily/task.py clear_campaign_first_time`，会为本次调用启用首通，并沿用上述队伍、预算、首领及领奖配置，不修改日常配置。

## 复刻活动

`revival_event_once` 根据当前活动身份处理关卡、首领、剧情、任务和讨伐证兑换。已完整完成的同一活动再次运行会跳过；未完成时保留原因供接续。账号切换后应设置不同的 `RevivalEvent.account_key`，避免复用其他账号的完成记录。活动身份不决定页面布局，未知的新布局会保留现场并停止。

高难与 SP 仅使用匹配当前活动、难度和模式的来源队伍，开战前检查角色身份与培养要求。队伍缺失或条件未知时不套用旧活动方案。战斗中减员、超时或无法确认结果有停止边界；不会点击会重置整场首领进度的“放弃”。[复刻游戏知识](../game-knowledge/revival-events.md)记录已观察到的地图与奖励规则。

## 结果与限制

运行记录保存在本地 `cache/daily/runs/`，查看每项完成状态及未完成原因。困难扫荡提交一次后等待回执与次数刷新，持续无法核实时有界停止，不再次提交。补跑会重读实际次数，跳过已用完关卡并继续领奖。胜利动画不等于首通，任务须核对实际关卡/首领标记。实机验证仅覆盖雷电 960×540，未验收项见[工程待办](../pending-validation.md)。视频攻略解析范围见[技术说明](../video-strategies.md)。
