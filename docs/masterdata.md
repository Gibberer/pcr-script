# 任务前置静态资料

`pcrscript/masterdata.py` 独立更新国服静态数据库；不连接设备，不读取账号、不登录游戏，也不需要模拟器启动或 root。任务日程与角色规则共用 `cache/redive_cn.db`，不是分别下载不同第三方版本。使用说明见[数据库更新](guides/database.md)。

## 来源与更新

公开 `source_ini/get_maintenance_status?format=json` 提供资源版本和 CDN。请求只含公共资源渠道参数及空玩家编号，不含账号凭证。客户端版本要求变化时，程序只接受响应中明确给出的数字版本并有限重试，不安装或启动客户端。CDN 地址限制在国服资源域名及客户端资源目录中。

通过当前版本的 `masterdata_assetmanifest_s` 定位主库资源包；同版本非精简清单提供 MD5。下载设置超时和大小上限，核对大小与 MD5 后，由锁定版本 UnityPy 提取唯一 SQLite TextAsset，检查 SQLite 完整性。资源包省略 Unity 版本，解析使用明确的格式版本；解析失败不能当作空数据库。

`data/masterdata_schema.json` 维护所需静态表、列的准确哈希标识和 SQLite 类型。字段名称参考[公开符号对照](https://github.com/cc004/autopcr/blob/main/data/rainbow.json)，并对照客户端静态主库的字段、类型、内容和游戏规则核实；运行时不下载该对照或重命名工具。映射包含日程、角色身份、技能、属性、专武和解锁条件，目前仅导出这些明确支持的表，不宣称完整覆盖客户端全部玩法。新增任务需要的表应在项目中明确添加并测试。

哈希列顺序变化不影响读取，新增未知列保留为未使用信息；缺少已知列或类型改变则拒绝新版本。禁止用行相似度、字段位置或同列数猜测表的身份。结构变化时修订项目映射及相应规则；不能自动执行外部 EXE 修复数据库。

在同目录临时区生成标准表名的本地库，连接关闭后原子替换，版本、资源来源、原始主库 SHA-256 和规则指纹随库一起发布。中断或验证失败保留旧文件。临时文件、下载的主库和实际运行证据不进入版本控制；测试只用合成静态数据。

默认六小时查询一次资源版本，版本相同无需下载主库。日常、独立任务准备和头像准备复用这个缓存。调用者可要求更短期限，但最长不超过24小时；更新时间不能代替版本号或表覆盖判断。网络或下载失败可使用24小时内验证过的同规则缓存，并在结果中标记 `stale`。没有合格缓存时抛出错误，不把所有日程置空；已确认新库结构不受支持时，即使有旧缓存也停止。规则指纹改变后重新提取。

## 前置判断与现场状态

`news.fetch_event_news()` 从同一静态快照生成兼容的 `EventNews`，附带 `source`。`runtime.run_script()` 在连接设备前读取资料、筛选日常，随后将快照交给活动分发器。分发器根据各独立日程跳过未开放类型，不再为确认未开放类型逐页导航。联动讨伐来自 `mre_schedule`，讨伐券与奖励券 ID 独立读取；开放后仍核验现场活动身份、时间及消费回执。

其他静态消费者继续通过标准表名查询同一数据库：角色衣装、技能、职能、属性、升星材料和专武定义。`game_ui.avatar_assets.ensure_database()` 只是共享更新器的兼容入口，头像图片来源与缓存另行管理。静态资料不是攻略，也不证明账号持有角色或满足战斗条件。

静态库适合筛选开放时间、关卡/角色定义与解锁规则；账号通关、每日次数、道具余额、当前培养和装配必须通过已验证的现场状态核实。不能以表内定义存在授权消费。过期缓存不用于“尚未开放某专武”的提前拒绝；相应消费者检查 `provider`、版本、时间和 `stale`。

国服无时区时间按 UTC+8 解析；日程结束边界排除。不同玩法分别读取，不以单一当前活动覆盖同期玩法。公会战旧规则仍将跨月日程限制为五天战斗期，塔表中长期开放记录也按原字段保留，未重新核验这些玩法规则。

合成回归在 `test_masterdata.py`、`test_news.py`、`test_activity.py` 和 `test_character_data.py`。当前版本可用不保证未来资源格式与玩法规则一直兼容。
