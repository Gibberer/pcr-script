# 视频攻略自动解析与 Agent 复核

地下城、深域及活动首领共用正式程序中的视频解析器，不要求 Agent 先生成队伍文件。当前实现是一组有明确边界的识别适配器，不是任意视频理解模型。角色身份识别成功与完整作业可执行是两个独立结果。

## 使用

GUI 中选择深域或地下城专项，在该任务的 `source_urls` 填优先链接，打开「仅获取并解析攻略」。深域还需在 `sources` 中给出 `stage` 和 `element`；正常游戏执行时它们由当前 NEXT 自动确定。可用的属性为 `fire/water/wind/light/dark`。不填写优先链接时由程序搜索；`sources.search: false` 可只分析指定来源。

命令行沿用正式入口，不另建 Agent 前处理命令。配置示例（链接由使用者填写，不包含真实作业）：

```yaml
Abyss:
  prepare_only: true
  source_urls: []
  sources:
    stage: '4-1'
    element: fire
    max_videos: 4
    max_pages_per_video: 4
    max_frames_per_page: 50
    max_video_seconds: 180
    parse_timeout: 900
```

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py abyss_push --config daily_config.yml
```

`Dungeon.prepare_only: true` 同理。仅解析时不连接模拟器、不编队、不开战；返回 `partial/blocked` 时命令退出码为 2，详细原因在报告里。这些开关只改变本次任务，不自动加入日常。

剧情活动和复刻活动在各自的 `StoryEvent.source_urls`、`RevivalEvent.source_urls` 中配置优先链接，`discover_sources: true` 启用自动检索。首领任务从实际活动名称、难度、模式形成查询范围。字段完整的来源队伍先按攻略培养条件核验；能确认目标范围和五人身份、但培养字段不全的来源进入标记为 `local_trial` 的账号试打分支：实时核验角色身份，记录当前可读培养状态及未知字段，不把账号状态写回攻略。SET 未知时试打暂按开启，假设写入报告。剧情活动的活动名须与活动情报和当前首页文本一致，视频分 P/画面须明确首领难度和模式。旧本地 YAML 仅在任务中显式设置 `use_local_teams: true` 时作为过渡回退；默认不依赖它。首领战开关保持原有默认值，不因发现队伍而自行开启。

关闭 `prepare_only` 后，深域在搜索当前关卡时直接调用同一解析器；字段完整且适用的方案才进入来源核验分支，账号当前培养不会反过来补写来源要求。地下城默认自动获取解析结果；现阶段路线适配只接受同一来源、普通四层齐全、首领春夏秋冬各一队且无成员冲突的四彩灵峰路线。若此范围内五人身份和阶段可确认但培养不全，`allow_local_trials: true` 会建立按账号现状试打的整条路线，仍执行跨队占用与开战前预检。多刀、垫刀、补刀、跨来源组合和其他区域规划仍需后续实现。旧本地方案仅在 `use_local_teams: true` 且自动路线不可用时回退，不自动覆盖。活动首领的 `local_trial` 会基于公共头像候选与本地技能职责提出单人替补，实际是否持有、角色版本和编队由游戏 UI 逐人核验；最多战斗次数和任务时限仍约束试打。地下城的跨队占用与多刀路线尚无安全的通用替补执行器。

## 自动准备和识别范围

1. 自动下载国服角色数据库与公共头像，关联完整角色衣装身份，生成批量特征矩阵。公共参考库位于 `cache/game/avatars/reference/`，与账号观察缓存分开。过期重查目录和远端图片，保存校验和、版本与来源；首次不需要已有索引。没有国服身份的头像保留未知 ID，不猜名字。
2. 搜索结果和指定链接走同一视频解析路径。先读视频身份、分 P，再挑练度说明及目标关卡；地下城默认最多解析 12 个分 P，覆盖普通四层与四季首领各自成段的路线。分 P 标题可在画面没有阶段文字时提供层数/模式证据，标题与画面冲突时拒绝该帧。公开播放下载有大小、时间、完整性边界，部分下载不发布为有效缓存。媒体位于 `cache/game/strategies/media/`。
3. 战斗画面检测五个规则排列的青色头像框，批量特征匹配，要求五名不同角色及至少两帧证据。黑帧、强遮挡、低分和相近候选保留未识别。当前只支持近似 16:9、无额外黑边的已知战斗布局。
4. 练度表通过头像与下方标签关联星数及明确专武文字；支持完整角色名后的等级、Rank、星数、技能等级、专武 1/2 和 SET 标签。编队页确认「队伍编组」后才使用剑徽/信息帧识别；不能把该规则套在战斗头像上。战斗 SET 支持文字拆为两行的「立即／发动」与青色状态；没有识别到该状态不自动记为关闭。
5. 从练度说明保留属性等级、属性技能、MP、突破等辅助条件与建议；识别到手动轴则阻止当作纯自动方案执行。人物培养事实仅在来源范围明确匹配时关联。分 P 外的说明文字需要明确关卡范围和完整衣装名，不将基础名自动对应到所有衣装。

头像库是可重建的本地运行数据。安装包和仓库包含通用获取/建库逻辑，不提交头像、数据库或真实作业；构建核心目录包含 `pcrscript/`、`images/`、统一依赖清单和 `runtime_defaults.yml`，不调用 `scripts/agent/`。

## 输出与未知信息

`cache/game/strategies/parsed/` 保存版本化 JSON：来源详情、获取/解析时间、目标范围、五人身份、多帧证据，以及每个字段的 `value/evidence/conflicts`。证据带来源 URL、CID、时间点、截图路径、方法和坐标；截图的坐标为保存图像的 1280×720 空间。`null` 表示未确认，不能当作 `false`。同字段冲突后保留冲突，不按最后一帧覆盖。

每个队伍的 `readiness` 与 `pending` 区分已读字段和仍缺信息。等级、Rank、星数、专武 1/2、技能等级、SET、适用范围及服区全部明确，确认固定 AUTO 开启且不存在未支持的全局要求/手动轴时，才转为来源方案；开战前仍要核验当前账号。来源数值中的 Rank 与星数按精确要求核对，更高值不自动视为符合攻略。`ready` 表示当前已支持字段通过校验，不保证视频没有其他未识别条件，也不保证能通关。`local_trial` 是另一种实验路径，不宣称符合攻略培养要求；报告逐队记录 `build_basis`、假设、账号观察和未知字段。首领目标或五人身份仍无法确认时没有可用试打种子，不能误用另一关的队伍。

当前明确未覆盖：任意排版、战斗星星图形的可靠计数、全局培养要求的账号核验、语音说明/ASR、评论图片与任意网页图片、复杂手动轴、特殊装备与支援/借角要求的完整结构化、多刀地下城规划。视频公共头像库已自动准备；活动/复刻运行时旧头像索引的空缓存自动补全仍需核查。未识别内容仍可查看原始帧，但不能宣称已提取。新增布局应针对证据扩展适配器，并保留旧场景回归。

## Agent 接管时的持续复核

Agent 接管任务时须复核脚本结果。GUI/CLI 独立运行仍由程序完成，不等待 Agent 批准。

Agent 接管时按报告检查来源与关卡、逐角色身份及培养开关、辅助条件、实际任务结果。必须查看对应原始帧/OCR/运行证据；同时看被脚本拒绝或跳过的画面，防止只复核已识别字段而漏掉额外要求。不能仅凭 `complete/ready`、截图存在或脚本退出码认定无误。

复核结果写入本地 `cache/agent/strategy-reviews/`：记录解析报告路径和 SHA-256、复核时间、查看过的证据、确认项、误识别/漏识别/冲突、仍未知项、是否修改通用实现及复验结果。未逐项检查时标记待复核，不能写已确认。发现的通用布局与识别规则同步写入 `docs/game-knowledge/`，注明实测/用户提供/推断待验证，待办写明复现命令与验收条件。

Agent 临时读懂一张图或修正一份本地数据，不等于程序已支持该场景。修复应进入正式识别模块；测试使用合成数据，真实帧及实际作业留在被忽略的缓存。对同一报告复验后保留前后结论，报告内容变化时重新复核。

## 验证

```powershell
./.venv/Scripts/python.exe -X utf8 -m unittest discover -s test -p test_strategy_video.py -v
```

2026-09-23 已实测公共头像/国服身份在隔离空缓存建立 370 个身份、1049 行特征，约 169 秒；单个多分 P 视频自动下载两个目标分 P 并解析约 129 秒（包括 OCR，非单次特征匹配耗时）。提取出一个五人战斗阵容、11 名角色的练度标签及4条明确专武 1 信息；辅助要求另行保留。来源未明确完整培养/服区，因此报告为 `partial`，未开战。后续变化和复核记录见知识库待办；不能把本次识别当作所有视频类型或地下城路线已验收。

SET 分行 OCR 和战斗 AUTO 切换已通过正式仅解析入口复验。AUTO 与五人 SET 分开记录；同一阵容出现开启/关闭变化时保留冲突，不猜切换时序。星级图形与密集表格仍待支持。
