# 工程验收待办

这里只列尚不能由离线测试替代的实现验收。游戏机制的未知状态见[游戏待观察状态](game-knowledge/pending-validation.md)。完成后删行并更新所属专题。

| 场景 | 验收 |
|---|---|
| 新工程首次日常 | 无账号配置的新工程由 GUI 显示默认任务；设置设备后运行并核对任务顺序、结果与保存配置。 |
| GUI 暂停、恢复与停止 | 正常任务在安全页面请求暂停并等待确认；恢复/停止后核对状态、耗时、锁释放和最终报告。见[运行诊断](run-diagnostics.md)。 |
| 干净 Windows 首次安装 | 从 Release ZIP 解压，完成核心下载、Python 与依赖准备；分别确认缺 Git/Python 与网络失败提示。见[发布](releases.md)。 |
| ADB 与其他分辨率 | 已授权设备上验证截图、坐标、导航、OCR、错误提示；离线适配不能代替游戏实测。多个设备指定 adb_serial。 |
| 视频到完整配队 | 空缓存、不同布局和真实辅助字段的来源解析；逐项核对身份、星数、专武、SET/AUTO、适用关卡及拒识。深域合集表格和宽画面战斗/编队/特装页已可取得部分五人身份；水 4-3 精确分 P 的备用下载取得五人多帧身份与 AUTO，风 2-5 的特装页和编队页交叉确认五人但 AUTO/SET 仍未知，逐人培养仍需完整来源复验。风 2-10 的半自动分 P 在正式报告中已跳过下载；超长分 P 下载前预检及搜索名额让位只有合成测试，仍需真实冷缓存运行复核。见[视频解析](video-strategies.md)。 |
| 来源候选缓存稳定性 | 光 2-10 在自动搜索排序变化后丢失前次有效视频；已改为短期保留同目标候选的公开视频 ID、重新取得元数据并按当前规则复查。解析器版本变化的候选保留有合成测试，仍需用真实检索变化复验；空缓存不应依赖既有候选。 |
| 深域连续胜利队复用 | 光 3-3～3-5 已实测上一关获胜五人经本关重新核验后直接胜利，跳过了预先下载攻略。保存队伍不符时先查本关来源、复用队在新关失败后再查来源的分支已有合成测试，仍需在游戏中自然出现时复验。 |
| 深域来源阵容试打 | 火 5-4、水 4-3～4-5、风 2-7～2-9 均核对不完整来源五人和账号身份装备，并取得战后推进；水 4-4 精确分 P 的 SET/AUTO 得到视频证据，角色按账号需求补片升星后试打成功。光 2-10 的五人来源阵容在搜索卡双人角色误判修复后完成身份与装备审计、无替补通关；来源培养、SET 和服区仍未明确，只属于本地试打。水 4-5 的 SET 及风 2-7～2-9 的 SET/AUTO 仍未知。光 2-7 的五人身份虽有多帧证据，AUTO 关闭；光 2-8 的五人来源带手动轴或未核实的全局强化要求，均未执行来源阵容。手动分 P、关卡不符和全局要求仍须保持拒绝；其他真实布局及冷缓存复验见[视频解析](video-strategies.md)。 |
| 深域战后剧情恢复 | 水 3-7 战后角色剧情曾让战斗超时并使撤退无法确认；重启后依据剧情跳过控件回到水 3-8，次数 8/10。需在单次连续运行中复验剧情跳过、战斗结果与历史记录闭环。 |
| 深域中断回执与停止 | 光 3-5 的 WIN 后团队战 CP 弹窗曾遮挡地图；下次运行由 NEXT 3-6 和次数减少补证胜利，历史对账已在实机发生。光 3-6 在战斗菜单打开时协作式停止，任务状态为 `cancelled`，业务报告仍为 `running`、试打记录为 `in_flight`；本场最终胜负和剩余次数未核实。下次自然运行需先核对地图，再验证中断战斗的安全预算和报告收尾。 |
| 深域运行耗时 | 完整来源视频下载与多帧识别、每关逐人身份和装备审计仍需较长时间。连续胜利队复用已减少部分来源解析；冷缓存搜索、下载、审计的耗时和可安全复用的证据仍待实机测量与优化。 |
| 地下城新区域完整自动路线 | 空缓存获取多组候选，核对账号与跨队占用、逐战损伤、最终通关和重跑跳过。见[地下城任务](guides/dungeon.md)。 |
| 旧日常异常与业务回执 | 自然遇到网络失败、未知弹窗或次数耗尽时，核对有界停止、重复消费防护和部分完成原因。 |
