# 地下城首通任务

按需运行（不自动加入每日）：

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py dungeon_first_clear
```

注册任务 `dungeon_first_clear`、配置段 `Dungeon`，与 GUI 和每日入口共用 Robot/RunSession。模拟器和游戏需已打开；从首页、冒险、特别关卡、目标地下城地图/详情或编队取消后识别。当前地图布局只针对极难7开发，未验证其他区域或非960×540实机，不应宣称通用地下城全支持。

## 本地方案

默认读取 `cache/game/strategies/dungeon_teams.yml`，实际阵容、来源和账号证据不提交。本次用户明确暂缓队伍信息的全自动获取；正式运行直接读取本地方案并实时搜索、核验，仍不等于空缓存全自动完成。

格式为 YAML 映射：`version: 1`、`area`、`parties`。每项队伍有唯一 `id`、`floor`（1–5）、`phase`（第五层必须明确当前阶段文字）、`source`、`members`（五个不同角色）。角色字段与活动共用：`name`（完整衣装）、`level`、`rank`、`stars`、`unique`、`unique2`、`instant`、`skill_level`；三个开关必须明确布尔值。`allow_deaths` 默认0。

先比较多套来源方案、账号角色、替换依据、跨队占用和补刀余量，再把选定路线写入 `parties`；互斥候选不能一起充当已选路线。首领层默认 `preflight: true`，第一场开战前逐队实时核验剩余首领路线；角色冲突或任一队不就绪，保留所有审查结果，不开战。`audit_only: true` 只预检。它检查编队可用性，不保证伤害足以通关。

队伍按列表次序筛选实时层数/阶段，每项至多尝试一次。相同成员需要用于不同普通楼层时，分别配置不同 id。每队可标明 `role: main/bridge/cleanup/finisher`，`source_damage` 是来源参考伤害而非账号预测；`max_hp` 可保护收尾队，只有读到首领血量不大于该值才允许选择。开战前仍重新核对当前队伍身份、培养和最终顺序。`preflight: false` 用于受控分批试验：先比较全路线与角色占用，明确记录备用队尚未完成的实时核验，再逐队核验开战；不能据此宣称整条路线已经可用。正式运行保留默认全路线预检。

头像无专武信息帧时，程序可自动到角色页按完整碎片名称确认衣装，仅识别「专用装备1预定今后登场」的未开放状态，再返回编队；证据只在本进程短时有效。其他未知状态继续阻止开战。

`build_basis` 默认为 `source`。本次用户另行授权按实测账号状态探索性试打时，试验队伍标为 `local_trial`，仍填写真实培养开关，并须本次运行显式开启 `allow_local_trials`；默认关闭，不能把试验方案称为原作业要求。

这类已获授权的试验可另设 `use_current_build: true`：成员仅填写有来源的完整 `name` 与 `instant`，程序实时读取身份、等级、Rank、星数、技能和专武开关，将实际状态及证据记入报告。任一培养状态未知仍不允许开战；它不判断账号状态满足原作业要求。普通来源方案不允许使用此选项，默认关闭试打的运行也不能加载它。

## 进度与保护

- 对目标卡片的「已完成！」标记进行区域关联，确认已完成即跳过，不执行扫荡。
- 未进入时核验挑战次数；已在区域中时允许0/1继续，不点整场「撤退」。
- 每队开始前保存来源、实际培养核验、层数和血量；结算后再次读取，层数上升/血量降低才是进展，不用战斗胜利文字代替整个地下城首通。
- 战斗超时/超出允许减员使用战斗菜单撤退。次数/任务总时限受限，未知弹窗保留证据停止。
- 状态保存在 `cache/daily/dungeon_state/`，按 `Dungeon.account_key`（缺省模拟器编号）和区域区分。多账号使用同一模拟器时必须配置不同 account_key。
- 当前账本支持同一次进度跨进程接续。程序亲自观察到新区域确认时，将旧账本保存在状态目录 archive/，再开启新轮次；重复确认不会重复归档。存在未核对的in_flight时拒绝新轮次。轮次隔离已离线验证；用户在程序外重开且停在中途时，不能据日期自动推断新轮次。
- 战斗前原子写入 `in_flight`；进程中断后不重放未确认战斗。实时确认层数上升时保存证据并自动恢复；仍在同层时需要先查看运行证据和实际游戏进度再人工核对这一条记录，不得为恢复而重置整个地下城。队伍 id 跨运行去重，修改方案时不要复用旧 id 表示不同队伍。
- 每次执行的报告、截图、事件位于 `cache/daily/runs/<run>/tasks/<序号>-dungeon_first_clear/`。
- 每场立即归档到同一状态文件的 `history`：来源参考值、实际成员/培养与 SET、前后血量/页面文字、保留伤害、角色消耗数、墙钟耗时和结局。未就绪审查单独记为 `audits`，不再当作已经消耗的战斗。墙钟耗时不是游戏内生存时长；伤害是结算保留值，撤退的临时伤害不能计入。
- 试打后依据数据选择有限重试、配装调整或有依据的替换；没有变化依据时不重复相同失败操作。现阶段不会自动推导替换或选择最优路线，仍需先准备经比较的本地路线；整条路线预检也不检查特别装备的具体分配。

本次用户授权的配装试验可启用 `auto_equip: true`（默认关闭）：每队身份/培养核验后，打开特别装备，使用游戏当前四项「稀有度」优先规则，允许调配其他角色的现有装备，检查十五槽均有可辨认的彩色装备后应用。只分配已有装备，不购买、不强化EX、不修改优先规则；设置变化或槽位未知会停止。保存配装前、设置与预览证据，后续队伍会重新配装，因此不能永久信任之前队伍的EX配置。稀有度自动分配是试验基线，不等于攻略要求的最优属性组合。
