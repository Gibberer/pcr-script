# 任务组织与执行

GUI、每日命令和单项命令共用 `pcrscript/tasks/` 中的 Task 注册表与 `Robot.run_task()`。任务按功能归档，与是否加入每日列表无关；注册名和实现文件见[项目结构](project-structure.md)。`pcrscript/game_ui/` 提供可共享的观察、识别与操作能力，`scripts/daily/` 只提供命令入口，`scripts/agent/` 用于分析和校准，不是正式任务的运行前置步骤。

## 任务能力

- `BaseTask` 定义上下文、配置、只读 `prepare()` 与执行契约，并用 `report_progress(label, current=None, total=None)` 上报业务进度，不携带图片匹配接口。步骤总数未知时只传说明，GUI 显示活动中的进度条；有明确上限时同时传当前数与总数。
- `ImageTask` 提供旧图片任务需要的模板匹配、动作绑定、设计坐标换算和动作序列进度；OCR 任务组合 `game_ui` 能力。
- `TimeLimitTask` 独立提供活动时间筛选，可与图片任务或 OCR 任务组合。
- `registry.py` 是唯一注册表；具体任务使用 `task_<功能>.py`，辅助模块不以 `task_` 开头。`task_combat.py` 中的编队与战斗子任务不单独注册。

旧图片任务若使用 `action_squential()`、`template_match()` 或设计坐标接口，应继承 `ImageTask`。动作通过 `ActionContext` 读取设计宽高，实际点击/滑动按最新截图尺寸换算。公开任务类从 `pcrscript.tasks` 导入。

## 配置与调用

`campaign_clean` 注册到 `task_activity.ActivityDaily`，按 `Activities.types` 分发 `story`、`revival`、`collaboration_raid`。剧情活动原实现 `task_story_event.CampaignClean` 是未注册的内部处理器，供复刻及显式剧情首通复用；联动、复刻旧注册名保留兼容。分发为每个处理器复制配置并指定独立输出目录，复用同一设备与运行会话。`Activities.options.<type>` 覆盖旧领域配置段，未声明字段不跨类型传播。各类型先读取共享静态快照中的独立日程，跳过未开放类型；开放后核实实机身份、时间与现场状态。静态库更新无需设备或 root，见[前置信息架构](masterdata.md)。

只有处理器结果已核实完成或不可用时才进入下一类型；未核账或未知结果停止分发。日常列表同时包含统一入口及其覆盖的旧独立入口时，在活动筛选前去重；旧入口未被统一配置覆盖时继续保留。GUI 将独立入口标为兼容类别，已有列表仍可编辑它们。用法见[活动日常](guides/activities.md)。

完整日常在连接设备前读取静态资料并复制 YAML 的 `Task` 列表，按活动情报筛选后依次调用 `Robot.work()`，不改写所传配置；GUI 批量运行先将启用项写入同一列表。单项入口调用 `Robot.run_task(name, *args, **kwargs)`，使用选定配置段但不修改每日列表。默认配置集中在根目录 `runtime_defaults.yml`。

`tasks/options.py` 共用正整数预算和布尔开关的默认值填充、类型与范围校验，返回新字典，不改写传入配置；布尔值不能作为整数预算。各任务声明自己的字段与上限，并负责领域、来源、装备等关联约束和旧配置迁移。接入该能力的任务在 `prepare()` 与构造时使用同一校验函数，非法配置在设备连接前报错。

```powershell
./.venv/Scripts/python.exe -X utf8 daily_task.py --config daily_config.yml
./.venv/Scripts/python.exe -X utf8 scripts/daily/task.py caravan --config daily_config.yml
```

任务需要首页时由注册参数 `requires_home=True` 声明，调度器在运行前导航；有自身导航的 OCR 任务和当前地图任务保持原起点。旧列表中无参数的 `tohomepage` 分隔项会跳过，带自定义参数的手动请求仍执行。活动任务先运行只读 `prepare()`，没有有效目标时可在连接设备前结束。

首次登录与任务间返回首页共用选择页退出逻辑，识别剧情活动关卡一览、追忆战扫荡选择、迷宫公会列表、深渊难度列表、前哨批量预览及未开战详情后再使用对应返回控件；不点击消费确认弹窗覆盖下的按钮。深渊入口也复用剧情活动列表的退出识别。扫荡结果须结合所属玩法判断，迷宫入口遇到追忆战回执会停止，交由追忆战任务核对。`EventUI.observe()` 识别动作循环已取得的画面，避免为同一次判断再次截图；识别到战斗计时与菜单时保留现场。探险地图有自己的菜单，须结合页面标题与导航识别，不能仅凭菜单判断正在战斗。

联动报酬列表按目标与普通报酬栏目标题定位各自剩余数，兼容多项目标造成的纵向位移。两类均明确为零且重置按钮可用时，共用首页导航可切换空奖池并关闭重置回执；列表未核实时停止，不穿透弹窗点击首页。兑换批量按钮低置信度时局部重读按钮及消费文字，保持原置信度要求，不退回左侧单张兑换。

活动数据库中的无时区时间统一按国服 UTC+8 解析；活动筛选、首日判断与日志显示均不受电脑本地时区影响。首日按国服完整日历日期比较，不仅比较日期中的日号。数据库来源、项目字段映射、缓存及原子发布统一由[静态资料模块](masterdata.md)维护；日程与角色资料共用同一来源，未知结构不按未开放处理。

## 结果与错误

每次调度将执行记录写入 `cache/daily/runs/<run>/tasks/<序号>-<任务名>/result.json`，任务报告与必要截图在同一目录；重复运行同名任务不会覆盖本轮其他任务。`events.jsonl` 记录 `task.result`，运行控制和异常证据见[运行诊断](run-diagnostics.md)。没有业务后置核验的旧任务只标记 `finished`，不能当作资源已确认的 `complete`。

每日结束时共用运行入口生成 `summary.json`，按实际执行顺序保留状态和原因。错误优先于部分完成，`partial` 或 `blocked` 汇总为 `partial`；仍有 `finished` 或其他未核验状态时不报告已核验完成。汇总只描述本轮已执行任务，不代表游戏全部每日目标已经达成。GUI 与 CLI 在关闭运行会话后处理业务退出码，部分完成不会产生额外异常现场。

首页任务领奖等待回执标题与关闭按钮同时清晰可读，且连续两次观察位置稳定，再保存回执并关闭；弹窗仍在时不把后方任务标签当作已回到列表，也不重复提交领取。

日程表最多等待15秒确认首页文字入口，然后只提交一次打开操作，展开期间等待完整书页，不再次点击可能已变为行内“执行”的原入口位置。日程表读取“交给可可萝”的独立完成数，数字裁剪关闭方向分类，避免把 `9/9` 旋转识别为 `6/6`。结算后保留列表位置时通过已核实的滚动条找回总数；共用滚动操作可接受调用方的目标页面判定，日程表在新画面中读清整表计数即确认到达，避免滚动条长度变化造成误报和多余回退。未提供目标判定的调用仍按滚动条位移及列表内容核验。整表完成时允许灰显的一键自动。处理中持续读取新画面并等待确认与结算，连续三帧的完成总数一致后才关闭；总数变化或持续未知时不声称完成，也不重放一键自动。超时报告当前可见余项与提示，跨页余项等未完成场景的验收见[工程待办](pending-validation.md)。

任务报告、消费状态和攻略缓存统一用 `run_session.atomic_json()` 写入：创建父目录，写入同目录唯一临时文件后原子替换，Windows 短暂占用时有界重试，失败时保留旧文件并清理临时文件。写入失败须向调用方传播；缓存可重建，待核对消费不能按缓存缺失处理。各玩法仍自行定义状态内容和解除条件。

单项任务在运行记录中显示 0/1 到 1/1 的任务级进度；日常列表沿用逐项计数。任务内部的 OCR 业务阶段和旧图片动作共用第二行进度，每次任务结束都会清除该行，避免下一项显示上项的进度。进度仅表示执行位置；最终业务状态仍以任务报告为准。

旧图片任务未声明步骤总数，或循环已超过声明总数时，只显示步骤编号；已声明且尚未超出上限时显示当前步骤与总数。动作进度条仍按当前序列的实际动作数计算。

单项异常向调用方抛出；每日列表记录错误并继续后续项。消费后不递归重放整任务；恢复必须先核对实际结果。旧任务中尚未有界的等待和缺少业务结果核验的场景见[待验证清单](pending-validation.md)。

团队战逐个读取首领详情时，复用刚确认的地图和详情页取消按钮；每次返回仍采集新地图，不重复识别没有输入变化的同一页面。扫描观察只用于本轮读取，模拟和实战准备仍独立重新确认首领身份、轮次与血量，行会进度刷新时丢弃本轮扫描结果。

首领生命值采用固定数字区的局部放大、关闭方向分类读取，不沿用整帧方向分类后的数字；低置信度、前导零或无效分母均拒绝，不能据此排除全部推荐。每次核对的当前／最大生命值写入运行事件，便于区分资料筛选、识别失败和真正无候选。

团队战血量、推荐伤害、推荐耗时及普通结算返还时间共用固定区域、关闭方向分类的高置信度数值读取；局部未知不回退整帧旧值。推荐耗时与实测返还时间共用90秒普通战、20秒奖励、8秒余量的预算规则。任务只覆盖 A/B/C 低难度阶段：普通刀推荐须参考伤害等于当前血量、模拟必须击杀，满血首领还须通过双刀预算，伤害达标不作为旁路；同一首领连续 `max_boss_failures` 次模拟未通过即记为超出低难度前提并换首领，不耗尽运行时限。实战结束同时核对普通／延长次数变化，记录已结算结果后再验证，核账失败保留 `in_flight`。

模拟搜索默认 `max_simulations=0`，只由运行时限和候选去重约束；显式正整数保留为程序搜索上限。达到上限抛出运行预算类结果，不能返回候选耗尽。生成数字图的真实OCR测试可用 `PCR_REAL_OCR_TEST=1` 启用，测试数据不使用账号截图或真实阵容。

团队战推荐淘汰按原因累计写入业务报告，伤害超过当前血量、参考耗时不满足双刀预算、缺员／受限及实际编队拒绝均记录运行事件；数值筛选事件同时包含血量、参考伤害和参考耗时。未完成报告附累计淘汰统计，不能用笼统的“没有队伍”替代识别失败。数字识别回归须经过实际局部裁剪和方向参数传递，只替换 OCR 引擎边界；这不代替真实图片识别验收。

团队战推荐列表在伤害文字区滑动，用滚动条位置核对是否翻页；列表中段连续滑动未生效须重试或报告操作失败，不能据此按候选耗尽结束。只有确认滚动条到达对应边界后，才完成向下扫描或更新后的回顶部。

团队战的编队身份合并、推荐行签名与已参战成员判断共用头像匹配条件：固定偏移特征余弦至少0.92，且逐图去均值特征相关度至少0.9。不能在身份合并阶段仅凭前者先复用队伍键，再到消费限制阶段补查；推荐行也需保留两种特征，避免不同候选共用已试标记。缺少必要特征时不回退旧规则；游戏内缺员与参战限制仍独立核验。实际头像与异装的验证要求见工程待办。

团队战不编辑隐藏筛选：该页条幅周期性闪烁、点击与滑动可被丢弃，整页扫描约需数分钟，而默认推荐通常已有可用队伍。战后结算页的「下一步」也可被丢弃，仍显示结算页时重点；入口遇到已结算页面直接离开，不重放已扣次数的战斗。`simulation_only` 为免费预演：按实战规则逐刀查找新队伍，模拟通过即记入本进程已参战集合，不打开实战编队。

## 回归测试

按功能定位 `test/test_<功能>.py`；跨入口调度见 `test_task_integration.py`，配置边界见 `test_task_options.py`，原子写入见 `test_persistence.py`。登录、设备启动、运行控制和 GUI 配置协议分别见 `test_home_login.py`、`test_device_adaptation.py`、`test_run_session.py`、`test_desktop.py`。

共用合成画面和输入回放放在 `test/ui_fixtures.py`，玩法页面放在对应的 `*_fixtures.py`。测试从夹具模块导入辅助函数，避免为复用页面而导入另一套测试；场景差异通过参数和 `subTest` 表达。回放只替换截图、输入和证据保存，任务的预算、状态迁移与消费核验仍执行生产逻辑。

先运行受影响测试；共享入口或测试组织变更再运行完整离线集：

```powershell
./.venv/Scripts/python.exe -X utf8 -m unittest discover -s test -p 'test_*.py'
```

回归应经过被修复的入口、分支与结果判定，只替换设备、网络、时间或消费边界；把目标逻辑本身 mock 掉只能验证调用关系。合成测试不替代真实布局与冷启动验收，缺口只保留在[工程待办](pending-validation.md)，验证后删除。
