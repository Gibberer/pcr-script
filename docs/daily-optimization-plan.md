## 实施批次

1. 先完成运行结果模型、启动错误与期限、有限恢复，补充必要的离线故障回放。每个消费动作必须具有“不重复执行”的恢复条件。
2. 接着实现启动状态判断与性能度量，选择本次实测最慢的任务优化等待/识别；保持日常配置顺序，先比较再调整导航。
3. 根据自然游戏状态补竞技场、研究、快捷扫荡的边界分支与验收；修复情报时区、缓存和实例选择。
4. 独立推进头像/作业自动获取；新活动首日由用户交付后才做首通实战验收。

后续每批记录修改前后任务耗时、截图次数、重复点击、完成/待办结果及证据。自然的资源不足、未开放不作为代码失败；没有复现的风险不标为实测故障。不为性能测试重复消耗、重置次数或制造满仓。
