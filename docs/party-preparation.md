# 攻略选队与战前培养

深域与深渊讨伐战共用账号编队、培养差距和特别装备准备。玩法任务只负责目标范围、导航、资源预算和战果核账，不能复制一套以账号现状替换攻略要求的选人流程。游戏机制见[配队与战前检查](game-knowledge/party-building.md)，来源取得与证据格式见[视频解析](video-strategies.md)。

## 职责与调用

| 模块 | 责任 |
|---|---|
| `tasks/strategy_sources.py`、`strategy_video.py` | 公共来源搜索、公共头像准备、解析与缓存；任务适配器核对本期、首领与难度 |
| `tasks/strategy_formation.py` | `StrategyFormation` 提供五人选择、实时审计、属性候选盘点、来源阵容与替补；`StrategyTarget` 传递目标，不导航到某个玩法 |
| `tasks/party_preparation.py` | 候选排序和有界来源遍历、来源已知培养要求核验、结构化培养差距、五星培养和特别装备准备 |
| `character_data.py` | 复用共享静态数据库中的完整衣装、技能与独立专武映射；只读缓存随数据库文件更新失效，不存账号装配状态 |
| `game_ui/character_equipment.py` | 完整衣装核验及只读专武页面；专武 1 等级与专武 2 强化阶段独立读取，未知布局不猜测 |
| `game_ui/ordinary_equipment.py` | 人物页六个普通装备槽的只读核验；分别保留未开放、已开放与穿戴状态，装备名未知不用于物品匹配 |
| `game_ui/character_search.py` | 编队与角色一览共用搜索输入、安卓输入条提交、搜索框复核和有界重试；页面仅传入各自坐标 |
| `game_ui/character_stars.py` | 五星开花／已解锁星级变更、独立秘石授权及回执 |
| `game_ui/special_equipment.py` | 特别装备观察、自动分配、提交后复核和配装外观比较 |

`abyss_party.py` 仅保留旧导入别名，不能再加入深域私有的公共能力。`SubjugationFormation` 仅适配本期属性和模拟后固定培养要求。其他玩法的特殊槽位布局仍由各自编队类声明；新调用方应组合公共能力，而非继承另一个具体任务。

## 选择与核验

共用人物页技能核验从列表顶部开始；向下采用130像素的正文滑动并保留重叠，核对滚动条与内容确实变化。长连结爆发说明不能通过大幅拖动滚动条跳过普通技能标题；仍须两项普通技能证明衣装，至少三项技能等级确认当前技能练度。

### 核验强度按失败代价

身份必须由头像或两项普通技能证明，来源声明的培养、专武和设置要求必须满足，不能因提速而放宽。来源没有声明的培养字段不读取：读到的账号数值不会阻止开战，只用于失败判重。

- 头像试打：来源未声明任何培养字段（`portrait_selection.declares_build()`，含 `declared_build`）时，`portrait_trial()` 按搜索结果的精确头像选入一至五人，不打开人物详情，报告标记 `portrait_trial`，由实战或模拟结果判断。头像不明确、搜索失败、本次已知缺角色，或同组成员在同一目标已失败过时，退回下述完整核验；完整核验会记录实际培养，作为之后是否重试的依据。已接入斗技场、联动讨伐、追忆首通与剧情活动首领；深渊沿用其独立入口。地下城、深域与迷宫仍走完整核验。
- 战前复核：选完人和开战前的身份复核（`inspect_current(full=False, expected_names=…)`）先比对槽位头像，每个槽位都被直接认出才通过；任一槽位不清时逐人打开详情。离开编队再返回的队伍不使用本次选人的排除推断。
- 失败代价：失败免费的玩法（斗技场、深渊前哨及首领模拟、联动讨伐首通、露娜塔模拟）完全由结果判断。会消耗资源的玩法（剧情活动体力等）同样不读取未声明的培养，但保留各自的尝试上限、预算和失败记录，同组成员在同一目标失败后不再换个来源名重试；国服尚未确认失败是否消耗的玩法按会消耗处理（追忆首通头像试打失败后默认不再自动开战）。

编队搜索已确认输入但明确显示「未搜索到该角色」时，最多再用两个较短关键词扩大候选。短词仅用于检索，人物页仍核对原要求的完整衣装、技能与培养；输入未确认时沿用原有重置重试及列表扫描，不把它当成空结果。

1. 玩法适配器先核验来源服区、目标、难度、五人身份、SET/AUTO 和未支持的全局条件。深渊来源未声明任何培养字段且编队类开启 `portrait_source_trial` 时，`select_by_portrait()` 按搜索结果的精确头像选入五人（其他玩法见上节头像试打），不打开人物详情，由后续实测判断；未开启五星培养时才走此路径。未精确匹配、搜索失败或已声明培养时退回下述完整核验。槽位头像只漏一人时，可由已精确选入的成员排除确定，其他情况不猜测。实战前重选同样只比较五人头像，配装仍须与模拟一致。
2. `source_candidates()` 按批取得候选；利用当前账号已观察的身份、属性候选和培养差距排序，先尝试所有原阵容，再按调用方的显式策略尝试缺员替补。空批次与全重复批次不触发角色盘点，继续在剩余批次预算内查找新候选。调用方按目标保留迭代器，失败后接续，达到批次／时间上限时结束遍历。深渊只从本期适用攻略选队，不回退到当前／保存编组；深域自身的本地试打策略另见其指南。头像候选只是排序依据，未匹配不证明未持有。
3. `audit_declared_build()` 只为来源缺失字段绑定账号观察；已声明的 Rank、星数、专武开关、专武 1 等级、专武 2 强化阶段等必须满足。替补不继承被替换者的培养要求，留下的原成员继续受原要求约束。
4. `cultivation_plan()` 记录逐角色当前值、目标、检查／补装／强化／不可兼容等差距。差距计划本身不授权消费，也不能当作培养完成。
5. `upgrade_party_stars()` 仅执行已启用的五星操作，遵守明确低星要求；消费前只豁免本次确实升到五星的成员的星级差距，其余成员的精确星级和其他培养要求仍须满足。离开人物页后重新选入五人并核验，保留来源 AUTO、逐人 SET 和伤害依据。
6. `prepare_special()` 在试打前分配现有特别装备并复核实际五人。自动选择的槽位未知时先取消预览并返回编队，再报告失败；深域与深渊入口共用取消逻辑，恢复遗留的设定／预览页时不会提交装备。深渊实战只读核对模拟时的槽位及装备外观；同样填满但换了装备也不沿用模拟授权。队伍/配装变化须重新模拟。

排序只决定尝试顺序，不宣称静态职能分数就是最优解。深渊以免费模拟的击杀，或存活至时限且符合当前首领剩余刀数预算决定能否实战，具体规则见[深渊指南](guides/abyss-subjugation.md)。替补队伍不继承原攻略伤害，须重新模拟并记录账号实测依据。不同 SET、AUTO、培养或有证据的伤害目标构成不同试验，仍受总模拟预算约束。已准备的队伍在返回编队时固定原培养要求；来源选人阶段的临时阈值通过独立入口处理，不能用于放宽实战核验。

## 数据库与画面如何配合

共享更新器取得的国服 `redive_cn.db` 包含 `unit_profile`、`unit_skill_data`、`skill_data`、`unit_unique_equipment`、`unique_equipment_data`。`character_data.py` 统一完整衣装、基础／进化技能和 `equip_slot=1/2` 的装备 ID／名称读取；沿用头像索引的可用角色 ID 范围（100100≤ID<200000），排除同名敌方单位。缺表、可用角色中的重复衣装或断开的装备映射保持未知，禁止创建空库作为成功缓存。

深域与深渊通过现有 `ensure_database()` 自动检查版本，角色资料最多复用 24 小时，独立于头像缓存期限。只有新鲜、完整的国服资料才用于提前拒绝“要求某件专武、该角色却无对应装备及进化技能定义”的来源，避免无效人物页往返。断网或旧资料继续作为候选知识，不据此断言装备未开放。数据库更新后查询缓存自动失效；跨服资料不作该判断。

公共库没有账号持有状态、已安装槽位、当前专武等级或强化阶段。既有编队徽标及近期有效现场证据足够时复用；攻略要求具体数值、证据过期或出现冲突才补人物详情。不能把装备定义表中有一行解释成账号已经装备，也不能把强化表的最高等级解释成当前等级。人物页只认已验证的衣装与独立槽位；单槽布局不反推专武 2，五星专武 2 需独立文案和五颗星共同确认。

原阵容已经确认缺员且本轮不允许替补时，直接继续其他来源，不再补查这支不完整队伍的装备。来源队伍的装备补查按角色限制为一次，只查看尚未确认的成员。重新编队后出现另一名未知成员时，仍可补查该成员；已经补查却仍未知的角色继续阻止开战，不能重复往返或沿用旧徽标推断。

补查返回后须重新选入本次计划的成员；游戏恢复的旧编组不能改写来源或已选替补。只有搜索确认缺员才进入替补流程。可先重新选入已确认持有的成员，再处理缺员替补。当前编队核验只打开实际占用槽位的详情，空槽不触发等待；部分选人成功不代表可以开战，战前仍须核对完整五人及其顺序。

属性候选盘点从已确认的列表滚动条顶部读到尾部，并核对拖动后的内容变化。属性图标或勾选打断卡框时，可从同排已识别卡片补充头像候选；这些候选只用于排序，选入前仍逐人核验。详情名省略衣装时，两项普通技能可确认实际衣装；请求某个衣装不能把另一衣装的技能和培养记录改写成目标。

搜索框只对已有实机证据的特定误读做校正，例如“菈比莉斯塔”被读成“莅比莉斯塔”；这只确认搜索提交，角色衣装仍由头像或实际技能核验。首领等级组合文字不清时可另读其数字区域，须保持高置信度并与原文字中的数字一致，不能降低整行门槛后直接授权战斗。

## 能力边界

通用培养标准适用于所有任务：等级、技能、普通装备和品级可全员拉满，由默认日常中 `schedule` 之后的 `upgrade_all_characters` 执行；升星和专武按需，只针对实测的上场成员；专武只做从无到有，不继续强化。因账号品级普遍拉满，攻略声明的品级在试打候选中按下限理解，能否使用由实测判断。

`cultivate_on_demand()` 在实测未达标后执行：对未到五星的成员调用 `upgrade_to_five`（攻略明确要求较低星数时不动，升星碎片兑换仍受 `allow_divine_amulets` 限制），并用 `install_missing_unique()` 补齐空专武。专武 1 所缺的记忆碎片可直接在女神的秘石商店购买至 50 个再制作安装，此路径不受 `allow_divine_amulets` 限制；其他素材不足则不购买，只记录并取消。专武 2 素材不足时放弃，写入报告的 `needs_user` 交给使用者。不使用专用装备辉光球（它会同时强化，且是稀有消耗品）。单次运行内每名角色只培养一次，确有变化才用同一攻略重测，单人失败不影响其他成员。目前只有深渊接入（`on_demand_cultivation`，默认开启）。

追忆首通可显式启用 `tasks/role_mastery_preparation.py`，复用 `game_ui/role_mastery.py` 将指定职能的四个节点提升到 Lv3，核对材料、确认预览、属性回执及券余额，并使用追忆共用状态记录消费。默认不培养或抽取；配置、预算和中断恢复条件统一见[追忆战场指南](guides/recollection.md#可选职能精通准备)。它不代替大师技能、属性强化或其他未支持全局条件的核验。

专武强化和上限解放不在标准内，没有执行器，也不实现。攻略已声明的专武差距仍记录计划并拒绝该候选；不把“有专武”当作已达到明确等级，也不把缺少专武 2 当作专武 1 已解决。专武制作与安装的确认页尚未真实走通，未知页面保留现场，见[工程待办](pending-validation.md)。

实机与冷缓存验收只在工程待办中维护。离线合成用例覆盖来源后续批次、原队优先、已知培养约束、零阶段专武 2、人物等级隔离、五星消费门禁及模拟后配装变化。
