# 礼物与特别装备

## 用户约定

2026-09-12 用户授权：特别装备堵住礼物箱时，走商店 → 特别装备 → 特别装备分解 → 一键分解 → 自动分解。使用用户在游戏内事先保存的自动分解规则，不修改设置；释放约 500～1000 格即可。默认 `Gift.free_slots: 750`，单次任务最多分解 1000 件，只进行一次满仓恢复。

## 已实测页面（960×540 设计坐标）

- 首页商店 (690,432)，礼物 (910,433)。切页可能先显示“正在进行数据连接”，必须等目标页面；固定 0.8 秒后连续点会丢失动作。
- 礼物箱标题 (480,42)，全部收取 (808,477)，取消 (588,477)。每批最多 100 件。勾选“除体力外确认收取”在 (361,476)，蓝色勾表示排除体力。必须先读当前勾选状态，再按参数切换，不能盲点反转。
- 收取礼物确认弹窗：确认 (588,479)。满仓弹窗标题“持有上限”在 (480,148)，确认 (480,370)；提示只说部分道具持有上限，不能单凭提示判定道具种类。
- 商店顶栏特别装备 (646,70)，右下“特别装备分解” (873,438)。进入“道具一览”的特别装备页。
- 特别装备持有数 ROI (495,65,605,103)，形如 `5000/5000`。右上“一键分解” (850,31)。不要点击单件分解或改装备。
- 一键选择模式下“自动分解” (694,387) 分成两行，OCR 可能分别读到“自动”和“分解”；“自动分解设定”在 (694,442)，不能混淆。
- 自动分解直接打开“特别装备分解确认”，消耗清单可滚动；确认分解 (588,479)。目前一批自动选择 50 件。确认后等待“回收结果”，确认 (480,479)，再读取新库存。结算后回到普通道具列表，下一批需再次点“一键分解”。
- 第一批实测库存 `5000 → 4950`；回收的货币/强化点数并不等于装备件数，必须以库存差值计数。若一次减少超过已验证的 50 件，停止后续分解并记录变化。
- 全屏 OCR 会漏掉蓝色“分解”按钮；已知确认弹窗内对 (485,450,695,509) 做 3 倍局部识别并复核蓝色按钮。不能因为漏字就点固定坐标。`test/fixtures/gifts/` 保存无账号信息的按钮和勾选框裁剪回归。
- 领取确认与成功结果的标题都叫“收取礼物”：确认正文是“要一键收取以下礼物吗”，成功正文是“收取了以下道具”。结果只有居中的确认按钮，须以正文区别，不能等待不存在的“收取结果”标题。

## 2026-09-12 实测结果

共自动分解 15 批、750 件：第一次探查 50 件，固化循环继续 14 批、700 件，库存到 `4250/5000`。随后收到积压特别装备 256 件，库存到 `4506/5000`。当前礼物箱只剩三项家具（魔女茶会套装、菲欧的假寐花、周年纪念气球架），列表底部已核对，没有剩余特别装备。后续满仓提示经检查特别装备未满，脚本停止分解并报告 `partial`；家具库存不在本次自动处理范围。

证据：`cache/agent/test_gifts.log`（逐批库存）、`cache/daily/gifts_run.log` / `cache/daily/gifts/report.json`（领取与非 EX 满仓分支）、`cache/agent/story_event/gifts_remaining*.png`（最终三项家具）。正式入口的重新执行已从前次领取结果弹窗恢复；不重复确认分解消费。
