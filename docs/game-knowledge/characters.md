## 后台操作（2026-09-12 实测）

- 2026-09-22 用户说明：单独发启动命令曾返回成功后进程退出，后来由用户启动成功。后续优先复用 `pcrscript.runtime.open_leidian_emulator(dnpath)`／`DNSimulator.start()` 的工程启动方式，并等待 `online()` 和后台截图确认；命令退出码为0不代表模拟器或游戏已就绪。此次工程启动修复尚未重新实测，不要据此声称该问题已解决。连接已启动实例时保留用户当前窗口，不另外启动重复实例。
- 同日实测：本次桌面环境中普通受限进程可能报告“未发现雷电窗口”，同一工程驱动在可访问模拟器的 Windows 会话内能够连接。先检查进程会话与运行权限，不据空驱动列表判定用户没有打开模拟器，更不能回退ADB。
- 2026-09-22 实测：`call.input` 偶尔没有实际写入搜索框，界面仍显示全名册。搜索后必须核对框内文本；最多重试3次，仍未写入应报「搜索词未确认」，不能据未匹配结果判定缺员。证据 `cache/agent/dungeon_route_candidate_search/candidate_克罗依_冬日_.png`（空框）与 `cache/agent/dungeon_candidate_verified_search/candidate_克罗依_冬日_.png`（成功）。已加入正式编队和候选搜索。
- 同日补充：搜索框也会把「千爱瑠」识别为「干爱瑠」，已复用姓名框的已验证字形修正，仅用于该明确名称；最终衣装仍由技能核验。证据 `cache/daily/runs/20260922-124321-31044-a90c0f/tasks/001-dungeon_first_clear/search_input_unconfirmed.png`，不可将这张有正确角色结果的截图判为缺员。
- 2026-09-22 实测：雷电「检测到手柄，已连接」通知会遮挡角色详情的名字与等级；截图证据在 `cache/agent/dungeon_whole_route_audit/current.png`（该次中断现场）。已加针对已观察提示的有限等待，提示自然再次出现时继续验证自动恢复，不能把被遮住的名字猜出来。

- 雷电 `DNDriver(click_by_mouse=True)` 使用后台窗口消息。`ldconsole list2` 第一列才是实例编号，不应按数组下标选实例。
- 后台中文搜索通过 `ldconsole action --index N --key call.input --value 名字`，异步入队，输入后需等待约 1 秒再点击搜索框外。
- 坐标按 960×540 归一化；截图失败时停止，不回退 ADB。Windows 中文文件名用 `cv.imencode(...).tofile(path)` 保存，避免 `cv.imwrite` 乱码。
- 共享 `EventUI.capture` 每帧按原始截图更新宽高，识别图像归一化到 960×540，点击/滑动从设计坐标换算回实际宽高。960×540、1280×720、1920×1080、1200×800 的换算已离线检查；仅 960×540 实机验证，非 16:9 布局/黑边适配另留待办。
- RapidOCR 3.9.2 会记住调用传入的 `use_det/use_cls` 标志。数字框使用 `use_det=False` 后，下一次全屏 OCR 必须显式恢复 `use_det=True, use_cls=True, use_rec=True`，否则只返回文本、没有 boxes。已用实际数字 1→0 的连续识别做回归测试。

## 头像数据

旧 YOLO 每个类别是角色 ID，新增类别需更新权重。新版使用游戏搜索＋一次矩阵查询的头像索引，新增素材不需训练。`scripts/agent/update_avatars.py --all` 下载[公开日服头像](https://redive.estertion.win/icon/unit/)，按 ID 对应本地国服数据库；未有国服名字的保留 ID。

2026-09-12 缓存 802 张头像、369 个身份。身份匹配有分数和不同角色间差值门槛；模糊匹配不能直接出战。详情省略衣装，错误基础名标签会污染索引，应只加入已核验身份的样本。
