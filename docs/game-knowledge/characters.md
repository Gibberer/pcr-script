# 操作与角色识别

## 后台操作（2026-09-12 实测）

- 雷电 `DNDriver(click_by_mouse=True)` 使用后台窗口消息。`ldconsole list2` 第一列才是实例编号，不应按数组下标选实例。
- 后台中文搜索通过 `ldconsole action --index N --key call.input --value 名字`，异步入队，输入后需等待约 1 秒再点击搜索框外。
- 坐标按 960×540 归一化；截图失败时停止，不回退 ADB。Windows 中文文件名用 `cv.imencode(...).tofile(path)` 保存，避免 `cv.imwrite` 乱码。
- 共享 `EventUI.capture` 每帧按原始截图更新宽高，识别图像归一化到 960×540，点击/滑动从设计坐标换算回实际宽高。960×540、1280×720、1920×1080、1200×800 的换算已离线检查；仅 960×540 实机验证，非 16:9 布局/黑边适配另留待办。
- RapidOCR 3.9.2 会记住调用传入的 `use_det/use_cls` 标志。数字框使用 `use_det=False` 后，下一次全屏 OCR 必须显式恢复 `use_det=True, use_cls=True, use_rec=True`，否则只返回文本、没有 boxes。已用实际数字 1→0 的连续识别做回归测试。

## 编队（2026-09-12，本期特别战斗＋编队，实测）

- 顶部“全部”在 (74,89)。搜索栏默认隐藏，向下拉角色列表至顶部，直到出现“用角色名搜索”或“重置”。搜索框 (480,136)，重置 (691,135)。
- 搜索用基础名字，不带衣装后缀。搜索结果首行卡片 x=60/166/272/378/483/589/695/801，y=177，约 100×99。活动加成箭头可能破坏卡片外框，不宜只靠轮廓检测。
- 当前队伍五槽中心：(96/205/314/423/532,452)。删除一名后其他成员向右对齐；清空时每次重读占用槽，不能只顺序点击五个旧坐标。
- 长按约 900 毫秒打开角色详情；只显示基础名字。例如公主日和莉显示“日和莉”，新年怜显示“怜”。两个普通技能名称可辅助确认衣装，专武状态优先读取实时剑徽。
- 详情能读等级、装备 Rank、当前星数、技能等级；“专武培养”入口在独立人物页面，不能从这个弹窗进入。
- 星数相邻边框会连在一起，应按六个固定槽采样；第六颗是粉色。

## 专武剑徽（用户提供；2026-09-12 观察到三种实际图案）

- 头像左下角交替显示星数和专武信息；信息帧同时显示红/蓝/黄色圆点。
- 无剑徽：没有开启专武。紫色单色剑徽：专武 1。紫色与金色混合剑徽：专武 1＋2。
- 不得在星数帧中把“没有剑徽”判定为未开。需连续获取信息帧；模糊、切换中或模式不明均记录未知。
- 样本：`cache/story_event/badge_frame_0.png`（星数帧）、`badge_frame_4.png`（信息帧）；匿名裁剪测试样本在 `test/fixtures/story_event/badge_*.png`。
- 单色样本包括星幽日和莉、公主日和莉、新年怜；混色观察样本是本体怜。星幽日和莉的独立人物页已直接确认专武 1 开启，等级 30，不要求其升级。
- 本体怜已在人物页直接确认：专武 1“盖尔手套”、专武 2“神风之剑”均装备，分别显示装备 1/2 强化状态，与混色剑徽一致。证据：`cache/agent/story_event/rei_equipment.png`、`rei_equipment2.png`。双槽中心约 (174,113)/(324,113)，单槽约 (249,113)，须先确认实际槽位再点。
- 图案规则与角色培养是两个层次：每轮读取实时图案，缓存只加速定位/提供证据，不替代当前状态核验。
- 部分圆点未开放时为空心灰色，例如本期艾拉。无剑徽的判断需要兼容实心彩色和空心灰色，至少连续两次看到有效信息帧；相关真实裁剪已加入离线测试。
- 2026-09-19 薇奥莉特实心三色圆点受头像背景影响，灰度模板可能漏判。增加固定位置红/蓝/黄联合校验，仍要求连续两帧且先检查剑徽。匿名样本 `test/fixtures/story_event/badge_filled_orbs.png`，复刻 VH/SP 十名角色实时核验后已实战通过，详见[复刻记录](revival-events.md)。
- 2026-09-12，SP＋模式 1 主队的五人搜索、衣装核验、培养读取、实时剑徽、最终顺序复核全链路通过。记录在 `cache/agent/story_event/audit.json` 和 `roster.json`，没有进入战斗。

## 人物页面（2026-09-12 实测）

- 底部“角色”(190,515) → 角色一览；向下拉显示搜索框 (480,90)、重置 (689,90)。列表为三列横向立绘，不能直接复用编队小头像定位。
- 进入“角色强化”后，专用装备标签 (816,76)，才能开花 (737,76)，技能强化 (657,76)。仅查看，不点击下方“装备/强化/解锁上限/才能开花”。
- 专用装备页显示实际装备名称、等级及“此专用装备1已强化至强化等级上限”等文字。未开放专武 2 的角色可能只有一个槽位，不能点击想象中的第二个坐标。
- 左下角头像约 (38,390,73,74)，可用已有头像索引确认衣装；标题仍可能只有基础名。才能开花页的记忆碎片名称含完整衣装，例如“日和莉（星幽）的记忆碎片”。

## 头像数据

旧 YOLO 每个类别是角色 ID，新增类别需更新权重。新版使用游戏搜索＋一次矩阵查询的头像索引，新增素材不需训练。`scripts/agent/update_avatars.py --all` 下载[公开日服头像](https://redive.estertion.win/icon/unit/)，按 ID 对应本地国服数据库；未有国服名字的保留 ID。

2026-09-12 缓存 802 张头像、369 个身份。身份匹配有分数和不同角色间差值门槛；模糊匹配不能直接出战。详情省略衣装，错误基础名标签会污染索引，应只加入已核验身份的样本。
