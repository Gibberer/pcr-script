### 2026-09-23 特征耗时基线（离线实测）

用户指出旧头像下载/训练工具不等于正式任务已实现通用头像识别。当前只有简单颜色特征匹配与预建缓存消费，自动素材准备/更新、通用视频识别及准确率验收仍未完成；本次仅测试耗时，不新增这些能力。

机器 Intel Core Ultra 7 255H，Python 3.13.5、NumPy 2.3.0/OpenBLAS、OpenCV 4.11.0。本地索引369个身份、1145条1728维float32特征，矩阵7.55 MiB。默认线程设置独立运行两次，下表为两轮中位数范围：

| 工作 | 耗时 |
|---|---|
| 读取已有NPZ索引（系统文件缓存未清空） | 30.03～33.38 ms |
| 提取5个查询头像特征 | 0.079～0.081 ms |
| 5个查询与全索引比较，Python逐特征循环 | 3.99～4.05 ms |
| 相同输入矩阵批量比较，仅分数计算 | 0.316～0.398 ms |
| 正式AvatarIndex.query，5头像提取＋比较＋不同角色排序/阈值 | 0.542～0.698 ms，P95约0.92～0.94 ms |
| 内存中802张公共头像重新提取特征 | 17.2～19.5 ms |
| 重新读取、解码802张公共头像并提取特征 | 402～420 ms |
| 模拟视频5头像各125种裁剪，一轮提取＋匹配＋排序 | 20.3～22.4 ms |

循环与矩阵分数最大绝对差4.77e-7，allclose(atol=2e-6)通过。注意库有多个素材/样本对应同一身份；两个建库测试为802张素材，与1145条现有索引不是同一数量。单线程另测5头像完整查询1.06 ms、视频裁剪工作量49.1 ms；默认线程在本机更快。5个独立矩阵查询约0.65～0.66 ms，与合批完整查询差距小，主要收益来自特征预计算及替代逐参考特征的Python循环。

复现：`./.venv/Scripts/python.exe -X utf8 scripts/agent/benchmark_avatars.py --output cache/agent/avatar-benchmark/default.json`；单线程加`--threads 1`。证据同目录`default.json`、`default-repeat.json`、`single-thread.json`，含每项样本数、中位数/P95、环境和数值一致性。测试只读现有库，不下载、不操作游戏。视频工作量用公共图片模拟裁剪，不包含定位、OCR、解码、下载；当前解析器最多尝试三种间距，因此一轮耗时不等于完整帧耗时。本次不是SIFT、深度特征或YOLO性能对比，也没有验证跨视频准确率；不能由此宣称已优于YOLO。下一步需用独立视频样本评估识别准确率及完整流水线耗时。
