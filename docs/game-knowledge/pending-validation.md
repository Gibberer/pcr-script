# 等待特定状态的验证

状态更新时保留实测日期与证据。以下项目不能因为离线测试通过就标记实战通过。

## 接续方式

用户常在对应活动开放后换新会话接续开发。先阅读本表和对应页面知识，再按触发状态实际验证；不要仅凭日期假定当前界面，也不要在条件不满足时反复试跑。每项保留：触发时间/状态、前置条件、执行入口、验收标准、最近证据、未完成原因和相关配置开关。完成后补日期、实际效果与回归测试；仍未验证的部分继续留表。

**列表式活动当前只启用重复日日常；复刻已单独增加一次性任务。** `StoryEvent.first_clear: false`、`bosses: false` 是示例配置、实际本地配置及代码默认值。2026-09-13 按用户要求去掉每日关卡全图检查，直接进入系统扫荡多选 H-1/H-2/H-3；列表未开放或不可扫荡时记入 pending 并继续领奖，不尝试首通。下一次首日用户交付任务后，先核对当期页面和作业，再临时启用相应开关实测，验证后决定是否纳入日常。不会自动安排提醒。
